# Querying OpenAI Codex / ChatGPT-plan usage & quota programmatically

Researched 2026-08-22, read-only: official docs via curl + GitHub sources (no installs). `developers.openai.com/codex` now 308-redirects to `learn.chatgpt.com` docs; `help.openai.com` articles return 403 to curl and web_search was unavailable, so plan-number claims are marked UNVERIFIED.

## Q1 — Is there an official endpoint for ChatGPT/Codex-plan rate-limit state? Yes (undocumented, OAuth-gated)

**`GET https://chatgpt.com/backend-api/wham/usage`** — first-party confirmed by the official CLI source ([openai/codex `backend-client/src/client/rate_limit_resets.rs`](https://github.com/openai/codex/blob/main/codex-rs/backend-client/src/client/rate_limit_resets.rs)): `PathStyle::ChatGptApi → {base}/wham/usage`, `PathStyle::CodexApi → {base}/api/codex/usage`; base auto-appends `/backend-api` for `chatgpt.com` ([client.rs](https://github.com/openai/codex/blob/main/codex-rs/backend-client/src/client.rs)). dsh-coding-plans calls it "the fixed endpoint used by the official Codex client" ([usage.ts](https://github.com/pengzhou267-ai/dsh-coding-plans/blob/main/packages/provider-codex/src/usage.ts)).

- **Auth**: ChatGPT-session OAuth bearer + required header `chatgpt-account-id`. dsh-coding-plans: `Authorization: Bearer <access>`, `chatgpt-account-id: <accountId>`, UA `dsh-coding-plans`. Tokdash ([codex.py](https://github.com/JingbiaoMei/Tokdash/blob/main/src/tokdash/sources/quota/codex.py)) reads `~/.codex/auth.json` (`tokens.access_token`), decodes the JWT for `https://api.openai.com/auth.chatgpt_account_id`, and also sends `originator: Codex Desktop`, `OAI-Product-Sku: CODEX`. pi-ai's OAuth uses the Codex CLI client_id `app_EMoamEEZ73f0CkXaXp7hrann` ([openai-codex.js on jsdelivr](https://cdn.jsdelivr.net/npm/@earendil-works/pi-ai@0.84.2/dist/auth/oauth/openai-codex.js)).
- **Sample response** (real scrubbed fixture [codex_usage.json](https://github.com/JingbiaoMei/Tokdash/blob/main/tests/fixtures/quota/codex_usage.json)): top-level `plan_type: "prolite"`, `account_id`, `email`, `user_id`, `rate_limit_reached_type`, `promo`; `rate_limit: {allowed, limit_reached, primary_window: {limit_window_seconds: 18000, used_percent, reset_at, reset_after_seconds}, secondary_window: {…604800…}}`; `additional_rate_limits: [{metered_feature: "codex_bengalfox", limit_name: "GPT-5.3-Codex-Spark", rate_limit: {primary_window|secondary_window}}]`; `credits: {has_credits, unlimited, balance: "4331.50…", approx_cloud_messages: [173,1083], approx_local_messages: [1083,5631], overage_limit_reached}`; `rate_limit_reset_credits: {available_count: 3}`; `spend_control: {individual_limit: {limit, used, remaining, remaining_percent}|null, reached}`; `code_review_rate_limit`.
- **Related endpoints** (same auth): `GET …/wham/rate-limit-reset-credits` (list; credits carry `title: "Full reset (Weekly + 5 hr)"`, `reset_type: "codex_rate_limits"` — [fixture](https://github.com/JingbiaoMei/Tokdash/blob/main/tests/fixtures/quota/codex_reset_credits.json)), `POST …/wham/rate-limit-reset-credits/consume`, `POST …/wham/usage/thread_usage/query` (authoritative per-thread `estimated_usage_credits_micros`/`_usd_micros`, [thread_usage.rs](https://github.com/openai/codex/blob/main/codex-rs/backend-client/src/client/thread_usage.rs)).
- **Not in public docs**: the `learn.chatgpt.com/codex/*` nav has no rate-limit/usage API page. Endpoint stability is UNVERIFIED — it's an internal ChatGPT backend API that the open-source CLI happens to use.

## Q2 — What tools actually do

1. **Call `wham/usage` directly with the stored OAuth token** (no model request needed): dsh-coding-plans `readCodexRateLimits()` ([usage.ts](https://github.com/pengzhou267-ai/dsh-coding-plans/blob/main/packages/provider-codex/src/usage.ts)) — refreshes OAuth via pi-ai's lifecycle, maps `used_percent → remainingPercent`, 401/403 → "sign-in needs renewal"; Tokdash `collect_codex_api_snapshots()` polls it (best-effort second call for reset credits).
2. **Parse response headers of model calls** — the official CLI's primary channel ([rate_limits.rs](https://github.com/openai/codex/blob/main/codex-rs/codex-api/src/rate_limits.rs)): `x-codex-primary-used-percent`, `x-codex-primary-window-minutes`, `x-codex-primary-reset-at`, `x-codex-secondary-*`; per-limit families `x-{limit}-primary-used-percent` (e.g. `x-codex-bengalfox-*` + `x-codex-bengalfox-limit-name: gpt-5.2-codex-sonic`); `x-codex-credits-has-credits|-unlimited|-balance`; `x-codex-promo-message`; `x-codex-rate-limit-reached-type`. No `retry-after` parsing for quota (SSE `retry` delay is honored separately).
3. **Parse SSE events**: `codex.rate_limits` event with `plan_type`, `rate_limits.primary/secondary {used_percent, window_minutes, reset_at}`, `credits` (same file).
4. **Local metering of CLI logs** (ccusage-style): Tokdash tails `~/.codex/sessions/**/rollout-*.jsonl` `token_count` events carrying `info.rate_limits.primary/secondary` + `total_token_usage`/`last_token_usage` (incl. `cachedInputTokens`, `cacheWriteInputTokens`), with replay/fork de-dup ([CODEX_USAGE_COUNTING.md](https://github.com/JingbiaoMei/Tokdash/blob/main/docs/development/technical-notes/CODEX_USAGE_COUNTING.md)). The CLI's app-server protocol exposes `getAccountRateLimits → {rateLimits, rateLimitsByLimitId, rateLimitResetCredits}` ([GetAccountRateLimitsResponse.ts](https://github.com/openai/codex/blob/main/codex-rs/app-server-protocol/schema/typescript/v2/GetAccountRateLimitsResponse.ts)).
5. **No scraping**: nobody scrapes HTML; GLFzr/dsh-opencode-go-quota has zero Codex code — it's OpenCode-Go-only (`GET https://opencode.ai/zen/go/v1/usage`), "Codex CLI-style" refers only to its tiered prompt warnings ([README](https://github.com/GLFzr/dsh-opencode-go-quota)).

## Q3 — Quota semantics

- **Windows**: primary = 5-hour rolling (18000s), secondary = weekly 7-day (604800s). Tokdash classifies by `limit_window_seconds` authoritatively, positional fallback (primary=5h, secondary=7d); a single returned window is weekly because "Codex temporarily omits its disabled 5-hour window"; idle 5h window reports phantom `reset_at` (nulled) ([codex_quota_windows.py](https://github.com/JingbiaoMei/Tokdash/blob/main/src/tokdash/codex_quota_windows.py)).
- **Per-model/per-feature buckets**: `additional_rate_limits[]` keyed by `metered_feature` (observed: `codex_bengalfox` ≈ a model lane), plus separate `code_review_rate_limit`. The CLI generalizes these as `limit_id` families.
- **Plans**: `plan_type` is returned by the API (fixture shows `"prolite"`); Plus/Pro/Business specifics — which plans have weekly caps, credit balances (`credits.balance`, `unlimited`), workspace `spend_control.individual_limit` — are account-dependent. Exact per-plan numbers are **UNVERIFIED**: not in any source I could reach (help center 403, no search); usage is exposed as `used_percent` only, never token counts, and OpenAI states limits are variable/demand-based (consistent with `approx_*_messages` being ranges). UNVERIFIED whether prompt-cache hits are discounted in plan quota — cached-token fields exist in usage events, but no doc I could read states the quota effect.

## Q4 — Auth modes: which gives plan-limit info

- Official [/codex/auth doc](https://learn.chatgpt.com/codex/auth) (fetched): two sign-ins — **"Sign in with ChatGPT for subscription access"** (plan credits) vs **"Sign in with an API key for usage-based access"** ("Codex uses standard API pricing instead of included ChatGPT plan credits"; some features unavailable under API key). **Plan-limit state (5h/weekly, wham/usage, x-codex-* headers) exists only on the ChatGPT-OAuth lane.**
- **API-key (platform) lane** is a different universe: org/project RPM/RPD/TPM/TPD usage tiers + `x-ratelimit-*` response headers incl. `Retry-After`, `x-ratelimit-remaining-tokens`, `-project-tokens` variants ([rate-limits guide](https://learn.chatgpt.com/api/docs/guides/rate-limits), fetched). `GET https://api.openai.com/v1/usage` → 401 "Missing bearer or basic authentication" without a key (org usage/compliance reporting, needs platform key — schema UNVERIFIED, no key here); `/v1/organization/rate_limits` → 404 in this environment. Neither returns ChatGPT-plan 5h/weekly windows.
- **dsh-coding-plans specifics** (parent's Q2 repo): OAuth only (no API-key path), credentials in `$DSH_HOME/coding-plans/codex-auth.json` (explicitly not `~/.codex/auth.json`, [index.ts](https://github.com/pengzhou267-ai/dsh-coding-plans/blob/main/packages/provider-codex/src/index.ts)); LLM traffic via pi-ai `openaiCodexProvider()` → base `https://chatgpt.com/backend-api` + `POST …/codex/responses` ([provider on jsdelivr](https://cdn.jsdelivr.net/npm/@earendil-works/pi-ai@0.84.2/dist/providers/openai-codex.js)); quota read = `wham/usage`, exposed host-side only (secret-free projection to the browser).

## Practical recipe for a third-party tool

Reuse `~/.codex/auth.json` (or run the CLI's OAuth: client `app_EMoamEEZ73f0CkXaXp7hrann`) → `GET https://chatgpt.com/backend-api/wham/usage` with `Authorization: Bearer` + `chatgpt-account-id` → render `rate_limit.primary_window` (5h) / `secondary_window` (weekly) `used_percent` + `reset_at`, `additional_rate_limits` as extra lanes, `credits.balance` if present; fall back to tailing rollout JSONL `token_count` events when no fresh network data. Expect 401/403 ⇒ re-auth, and no uptime/stability guarantee (undocumented API).
