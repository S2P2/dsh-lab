# OpenClaw: personal-agent gateway architecture & capability surface

**Baseline for:** Agent Harness Capability Map (profile #2 of 18)

**Verdict.** OpenClaw is the anti-DSH along almost every axis except plugin rhetoric: where DSH is a composition kernel whose product surface is whatever you mount, OpenClaw is a *productized single-operator assistant* — one long-lived Gateway daemon (default ws://127.0.0.1:18789) that owns chat-channel connections (WhatsApp/Telegram/Slack/Discord/Signal/iMessage…≈30 channels), routes every inbound message into keyed sessions (main session = one rolling cross-channel conversation), runs an embedded agent loop with pluggable **agent runtimes** (its own loop, or Codex/Copilot harnesses, or `claude-cli` CLI backends), persists **SQLite-first**, and reaches you wherever you already are — including phone/desktop companion apps acting as paired **node** peripherals with camera/screen/location/computer-use command surfaces. Its two deepest divergences from DSH are (1) a real cross-session **memory system** (Markdown files + retrieval + background "dreaming" consolidation) and (2) a first-class **scheduler** (cron/heartbeat/automations + webhook/event triggers). Structurally the sharpest shared instinct with DSH: both treat the *model-visible context* as the scarce resource with hard budget caps, deterministic ordering for cache stability, and deferred invalidation — converged design values, independently stated. Compositionally OpenClaw is shallower: one extension lane (a plugin SDK around a sealed Gateway core) versus DSH's every-capability-is-a-seam.

## Architecture profile

### 1. Positioning & runtime shape (D1)
- Single-operator personal assistant; **one long-lived Gateway process per host** owns all messaging surfaces and emits events (`agent`,`chat`,`presence`,`health`,`heartbeat`,`cron`) [src: docs/concepts/architecture.md#Overview].
- Runs as supervised daemon (launchd/systemd/Scheduled Task via onboard); foreground `openclaw gateway`; health over WS [src: docs/concepts/architecture.md#Operations-snapshot].
- Agent loop = serialized per-session run: intake → context assembly → inference → tools → streaming → persistence; `agent` RPC returns `{runId}` immediately, streams tool/assistant/lifecycle deltas; `agent.wait` joins on lifecycle end/error [src: docs/concepts/agent-loop.md#Run-sequence].
- **Agent runtimes**: provider (auth/models) ⊥ model ⊥ agent-runtime ⊥ channel are separate layers. Embedded harnesses: built-in `openclaw` loop + plugin harnesses `codex` (Codex app-server — default for `openai/*` models when enabled), `copilot`; CLI backends e.g. `claude-cli` execute the selected model ref through Claude Code [src: docs/concepts/agent-runtimes.md]. `/codex bind|threads|resume|steer|stop` drives Codex threads from chat.
- Transcript writes are fenced by durable writer claims: admitted run records `activeWriterRunId`; appends/rewrites pass `expectedWriterRunId`, verified synchronously in-transaction so superseded runs cannot commit stale data; per-agent SQLite writer queue + state-dir lock serialize processes [src: docs/concepts/agent-loop.md#Queueing-and-concurrency].

### 2. Gateway control plane (D16/D19)
- Typed WS API: `{type:req,res,event}` JSON frames; mandatory first-frame `connect`; pre-auth cap 64 KiB; discovery via `hello-ok.features.methods/events`; structured errors incl. `MISSING_SCOPE{missingScope,requiredScopes}`; idempotency keys required on side-effecting methods; W3C `traceparent` per request frame; **no event replay — clients refresh on gaps** [src: docs/gateway/protocol.md#Transport-and-framing, #Invariants].
- Handshake trust: gateway sends `connect.challenge` nonce; signature payload v3 binds `platform`+`deviceFamily`; paired metadata pinned, repair-pairing on change [src: docs/concepts/architecture.md#Pairing-and-local-trust].
- Public versioned contract shipped as npm `@openclaw/gateway-protocol` (TypeBox schemas → generated JSON Schema → generated Swift models) and reference `@openclaw/gateway-client` (browser-safe entry) [src: docs/gateway/protocol.md#npm-packages, #Protocol-typing].
- Same HTTP port serves WebChat, Control UI, hosted widget docs `/__openclaw__/canvas/`, A2UI renderer assets `/__openclaw__/a2ui/`, OpenAI-compatible HTTP API, tools-invoke HTTP API [src: docs/concepts/architecture.md#Overview; docs/gateway/{openai-http-api,tools-invoke-http-api}.md existence].

### 3. Trust, pairing, security (D13/D14)
- Device identity on every WS client (operators + nodes); new device ⇒ pending pairing approval ⇒ device token; loopback auto-approved; LAN/Tailnet requires explicit approval; private-CGNAT pairing can be auto-approved via SSH proof-of-machine-ownership roundtrip [src: docs/concepts/architecture.md; docs/gateway/pairing.md via docs/nodes/index.md#Pairing].
- Operator scoping: connection declares role+scope; method authorization failures enumerate `requiredScopes`; node-command approval tiers escalate (`system.run` needs `operator.admin`) [src: docs/gateway/protocol.md; docs/nodes/index.md#Approval-scope].
- Security doctrine lives beside a formal THREAT-MODEL ATLAS + formal-verification + incident-response docs [src: docs/security/THREAT-MODEL-ATLAS.md etc., existence]; execution-identity audit doctrine: opt-in diagnostic provenance, immutable spawn lineage, tri-state invoker evidence, decision receipts, never authorization [src: AGENTS.md#Execution-Identity-Audit].
- Secrets: channel creds in `~/.openclaw/credentials/`; shared model auth profiles in `state/openclaw.sqlite` with agent-local read-through overrides; SecretRef failure isolates to smallest owning surface; **gateway starts degraded, not refused**, with redacted diagnostics [src: AGENTS.md#Security-Release; docs/auth-credential-semantics.md].

### 4. Channels (D10)
- Inventory (generated catalog): bundled core = Telegram, WebChat, A2A, Reef; official plugins (install on demand) = WhatsApp, Discord, Slack, Signal (signal-cli), iMessage (native `imsg` JSON-RPC stdio preferred; legacy BlueBubbles), Microsoft Teams, Google Chat, Matrix, IRC, LINE, Nostr (NIP-04), Twitch, Zalo×3, SMS/Twilio, Synology Chat, Nextcloud Talk, Mattermost, Feishu, QQ, Tlon, Buzz/Raft/ClickClack; external = WeChat(openclaw-weixin), WeCom, Yuanbao [src: docs/channels/index.md#Supported-channels — GENERATED catalog].
- Transport hints: WhatsApp = Baileys invariant ("exactly one Gateway controls a single Baileys session per host"); Telegram = grammY; Slack = Socket Mode/HTTP/relay; iMessage via stdio helper [src: docs/concepts/architecture.md#Invariants; docs/channels/slack.md,imessage.md summaries].
- Routing is deterministic, host-configured — "the model does not choose a channel"; replies go back to origin; outbound targets accept channel prefixes only as hints [src: docs/channels/channel-routing.md#Key-terms,#Outbound-target-prefixes].
- Access control: `allowFrom` per channel + reusable `accessGroups` sender lists keyed by channel id; pairing flows per platform; bot-loop protection; guarded inbound recording protects pinned owner `lastRoute` [src: docs/channels/channel-routing.md#Main-DM-route-pinning; docs/channels/access-groups.md].

### 5. Sessions (D15/D8)
- Every inbound source maps to a session: DMs share **main session** by default (`agent:<agentId>:main`, personal-agent default — heartbeats wake it, background work reports to it, activity converges on it); groups/rooms isolated per id; cron fresh per run; webhooks per hook [src: docs/concepts/session.md#How-messages-are-routed; docs/concepts/main-session.md].
- `session.dmScope`: `main` | `per-peer` | `per-channel-peer` | `per-account-channel-peer`; `identityLinks` merge one human across channels; `session.groupScope` can collapse groups into main via bindings [src: docs/concepts/session.md#DM-isolation,#Group-and-room-routing].
- Session key grammar carries channel/group/thread/topic ids (e.g. `agent:main:discord:channel:123456:thread:987654`) [src: docs/channels/channel-routing.md#Session-key-shapes].
- **Channel docking**: move a live session's reply route to another linked channel without resetting it [src: docs/concepts/channel-docking.md; docs/concepts/session.md#Dock-linked-channels]. Incognito sessions (Control-UI initiated) live memory-only, skip transcript archive + memory flush; Codex-backed incognito also ephemeral harness-side [src: docs/concepts/session.md#Incognito-sessions].
- Same session continues across surfaces (Control UI / terminal / coding harness) via session synchronization and attachment [src: docs/concepts/session.md intro; docs/concepts/session-attachment.md existence].
- Sandbox/tool-policy derive a per-account direct-chat runtime key even when history shares main — so a Telegram-originated DM ≠ local trusted run [src: docs/channels/channel-routing.md#Guarded-inbound-recording area].

### 6. Nodes / devices (D11)
- Node = companion device (macOS/iOS/watchOS/Android/headless) connecting with `role:"node"` exposing `camera.*`,`device.*`,`notifications.*`,`system.*` via `node.invoke`; Apple Watch uses signed HTTPS polling (watchOS networking limits); nodes are peripherals, never gateways [src: docs/nodes/index.md].
- macOS menu-bar app runs node-mode internally (widget panel `canvas.*`, camera, screen, notification, **computer-control**) while remaining sole gateway connection [src: docs/nodes/index.md#macOS-node-mode].
- Pairing scope follows declared commands (commandless < non-exec < `system.run` needing `operator.admin`); N-1 protocol-version window for staged fleet upgrades; superceeded retry requests emit `device.pair.resolved` [src: docs/nodes/index.md#Version-skew].

### 7. Tools (D3/D12)
- Tools = typed functions surviving layered gating before the model sees them (profile → allow/deny → byProvider → sandbox policy → channel permissions → plugin availability) [src: docs/tools/index.md#Choose-tools].
- Named built-ins seen in docs: `exec`, `read`,`write`,`edit`,`apply_patch`,`process`, `browser`, `web_search`, `message` (channel send), `image_generate`; retrieval-style tools `memory_search`/`memory_get`; `automations` (alias `cron`), `sessions.reset`, `session_status(model=…)`, `node.invoke` families, `show_widget`, progress cards [src: docs/tools/index.md; docs/concepts/memory.md; docs/automation/cron-jobs.md; scattered per-page docs]. Exhaustive catalog not enumerated this pass.
- Three-control exec ladder: **sandbox**(where: off/non-main/all × backend docker|podman|ssh|openshell|daytona × scope agent|session|shared × workspaceAccess none|ro|rw) vs **tool policy**(which: deny wins; group:* shorthands) vs **elevated**(exec-only escape via `gateway` or `node` target; cannot bypass required creator-role sandbox) [src: docs/gateway/sandbox-vs-tool-policy-vs-elevated.md].
- Sandboxing off by default; note inside docs: "not a perfect security boundary"; bind-mount piercing audited twice (normalized + resolved ancestor), docker.sock hand-over warned; network default none [src: docs/gateway/sandboxing.md].
- Exec approvals: chat-directive `/exec` and `/elevated` gated to authorized senders (directives stripped from model view, persist when sent alone) [src: docs/tools/exec-approvals.md existence; docs/tools/slash-commands.md#Three-command-types].
- **Browser**: dedicated managed Chrome/Brave/Edge profile controlled via loopback local service inside the Gateway — tabs, clicks, types, snapshots, screenshots, PDFs, download-metadata returns (Playwright-backed profiles), bundled `browser-automation` skill; separate `user` profile attaches to your real signed-in Chrome via Chrome DevTools MCP; sandboxed-browser variant exists under docker backend [src: docs/tools/browser.md].

### 8. Skills & plugins (D4/D2)
- Skills = `SKILL.md` packs (YAML frontmatter, markdown body) loaded from 6 precedence tiers (workspace > project `.agents` > personal `~/.agents` > state-dir > bundled (+custodian-library tier) > extraDirs+plugins), filtered by environment/config/binary-presence at load; grouped layouts discovered ≤6 levels; slash-name collision = higher tier wins; whole-file loading (no windowed reads) [src: docs/tools/skills.md#Loading-order; AGENTS.md#Architecture guidance-served-whole].
- **Node-hosted skills**: connected node publishes its local skills into the agent list dynamically (deterministic node-prefix naming; vanish on disconnect) [src: docs/tools/skills.md#Node-hosted-skills].
- **Skill Workshop** = review/approve agent-drafted skill proposals UI; Self-learning doc family extends the loop [src: docs/tools/skills.md cards; docs/tools/skill-workshop.md, self-learning.md existence].
- Plugins extend via `openclaw/plugin-sdk/*` manifests only — core stays plugin-agnostic; channels stay transport-only (no product command trees in adapters); plugin kinds span channels/providers/tools/runtime-hooks/context-engine/UI; plugin permission requests at install; bundled vs external-official packaging split [src: AGENTS.md#Architecture; docs/plugins/sdk-overview.md,manifest.md,plugin-permission-requests.md existence; docs/plugins/reference.md generated inventory].
- Named pluggable slot example: **context engine** — `plugins.slots.contextEngine` selects third-party assembly/compaction/recall implementations over the built-in `legacy` engine [src: docs/concepts/context-engine.md#Quick-start].
- Distribution: ClawHub marketplace — owner-scoped publishing (`@owner/pkg` namespace enforcement, org roles, releases/changelogs), skills + npm-style plugin packages; community curation/trust docs sibling [src: docs/clawhub/publishing.md].

### 9. Memory & state (D7/D15)
- Memory = plain Markdown in the agent workspace (`~/.openclaw/workspace`): `USER.md` (user-model directives w/ supersede-in-place), `MEMORY.md` (curated durable layer, bootstrap-loaded w/ file budget + truncation-instead-of-loss), `memory/YYYY-MM-DD[-slug].md` daily notes (indexed by `memory_search`/`memory_get`, today+yesterday autoloaded on bare `/new`), `DREAMS.md`; "The model only remembers what gets saved to disk; there is no hidden state" [src: docs/concepts/memory.md#How-it-works].
- **Dreaming**: default background sweep distills daily notes into MEMORY.md; heartbeat does zero maintenance [src: docs/concepts/memory.md#What-goes-where]. Sibling docs: user-model, standing-intents, active-memory, memory-search, provenance/deletion, dream mechanics; pluggable engines Honcho / QMD; LanceDB/wiki plugin memories [src: docs/concepts/{user-model,standing-intents,active-memory,memory-*}.md existence].
- Action-sensitive memory doctrine: capture safe-to-act timing/expiry/handoff constraints alongside facts [src: docs/concepts/memory.md#Action-sensitive-memories].
- Cross-harness import: Control UI imports Markdown memory from Codex (`~/.codex/memories`), Claude Code (`~/.claude/projects/*/memory`), Hermes — quarantined under `memory/imports/`, indexed not merged [src: docs/concepts/memory.md#Import-from-coding-assistants].
- Storage doctrine: **SQLite only** for runtime state (`state/openclaw.sqlite` global + `agents/<id>/agent/openclaw-agent.sqlite` per-agent; Kysely, synchronous-commit sections, versioned schemas w/ migration owner = `doctor --fix`; integrity-check quarantine; downgrades unsupported; JSONL/files banned except product artifacts) [src: AGENTS.md#Architecture storage-bullets; docs/reference/database-schemas.md headings].
- `/new`,`/reset`,compaction,pruning,search,state-awareness,session-tools doc families exist under concepts/session-* [titles verified; internals not extracted].

### 10. Scheduling / background work (D9)
- **Automations** (alias of old cron CLI): jobs persisted in shared SQLite; kinds `--at`(ISO/relative), `--every`, `--cron`(+`--tz`, top-of-hour auto-stagger ≤5min), `--on-exit` (event trigger on watched command), `--stream-command` (fire from supervised long-running process lines); delivery to chat channel/webhook/nowhere; per-run timeouts (60-min scheduler watchdog, isolated-setup phase watchdogs); overdue isolated runs rescheduled—not replayed—on startup; structured denial vs interim-reply detection prevents false-green completions [src: docs/automation/cron-jobs.md#How-automations-work,#Schedule-types,#Isolated-run-hardening].
- **Heartbeat** = separate always-on wake cadence into main session (active hours, min-spacing, flood control, busy retries, coalesced windows); "Automations vs Heartbeat" selection doc; legacy heartbeat `tasks:` migrated by doctor into ordinary automation jobs [src: docs/automation/cron-jobs.md#Heartbeat-task-migration; docs/automation/cron-vs-heartbeat.md].
- **Background tasks** = persisted activity ledger (queued→running→succeeded|failed|timed_out|cancelled|lost) for ACP runs, subagent spawns, automation runs, CLI ops; push-driven completion wakes requester session/heartbeat instead of polling; terminal records pruned (7d/24h) [src: docs/automation/tasks.md#TL;DR].
- Inbound event automation: webhooks, Gmail PubSub, IMAP poll, standing orders [src: docs/automation/{webhook,gmail-pubsub,imap,poll,standing-orders}.md existence].

### 11. Models & providers (D5)
- Two-stage resilience: **auth-profile rotation** within provider (cooldowns, multi-account pools) then **model fallback** chain from configured `fallbacks`; selection-source policy keeps user session overrides strict (report failure, never silently answer from unrelated fallback); turn-local fallback w/ transition notices; overload-exhaustion retry loop (≤10, backoff, one status notice); `FailoverError` with per-attempt detail [src: docs/concepts/model-failover.md#Runtime-flow,#Selection-source-policy].
- Subscription OAuth: ChatGPT/Codex OAuth stored under canonical provider `openai`; Anthropic Claude-CLI reuse sanctioned per cited staff guidance; unified `openclaw models auth login --provider <id>`; PKCE token sink rationale (refresh-token rotation collisions across consumers) [src: docs/concepts/oauth.md].
- Local/self-hosted: ollama, lmstudio, vLLM, sglang, litellm proxy, llama.cpp, cloudflare-ai-gateway, vercel-ai-gateway, clawrouter…; ~60 provider dirs in `docs/providers/` [inventory].
- Usage tracking, retry backoff, timezone handling doc families exist [titles verified].

- Native surfaces: macOS menu-bar app (node + UI), iOS/iPadOS & Android apps (shared session-list digest state), Apple Watch talk, plus docs/web/{tui.md,dashboards.md,notifications.md} (TUI, metrics dashboards, notifications) [src: docs/web/*; docs/platforms/* inventory; apps/{macos,ios,android,linux} inventory].

- Chat-side UX: directive system (`/think /fast /verbose /trace /reasoning /elevated /exec /model /queue`) stripped pre-model, persist-alone semantics; inline shortcuts (`/help /commands /status /whoami`); host-shell escape `! <cmd>`; doctor/security-audit/logs/tasks CLIs [src: docs/tools/slash-commands.md#Three-command-types].

### 14. What DSH has that OpenClaw does not surface (absence is data, reverse direction)
Findings limited to docs/tree reviewed — OpenClaw certainly has engineering here, just not productized as named seams: no config-layered composition grammar (profiles/bundles/patch rows; plugins are manifest-registered, swap = config+restart), no swimlane event dispatch modes (waterfall/emit/parallel/serial contracts), no runtime-invariant companion checks over streams, no headless stdout contract / one-shot exit-code semantics, no embedding SDK (JSON-RPC server/client, Python) beyond gateway clients, no in-session dynamic-plugin authoring, no plan-mode/goal-objective constructs in the reviewed docs (progress/goal cards exist as UI artifacts), no oversized-output spill/pre-pruner pair, no typed LSP navigation seam. DSH-side compositional depth remains unmatched on the evidence gathered.

## Delta — orchestration-adjacent surfaces (2026-08-28, #33)

Full findings in `openclaw-workboard-delta.md` (@ `533319b`). Corrections to this profile:

- The five title-only names are **not one multi-agent cluster**. **Workboard** is the substantive finding: a durable local orchestration layer above Gateway subagents — dependency-aware cards, claim tokens + TTL/heartbeats, deterministic per-card worker sessions, bounded dispatch (≤3 workers, one card per owner) with stale-claim recovery, `workboard_specify`/`workboard_decompose`, structured completion/block protocol, replay-safe notification cursors, workspace-authority re-intersection at dispatch; 35 `workboard_*` tools. - **Fleet** = isolated per-tenant instance cells (Docker/Podman lifecycle) → deployment/multi-tenant isolation, **not D8**; **mantis** = visual QA evidence infra, Not applicable; **swabble** = macOS wake-word/voice ingress daemon, plugin-plausible under D10/D12, not orchestration.
