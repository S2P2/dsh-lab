# NemoClaw + OpenShell profile: NVIDIA's sandboxed agent runtime stack

**Verdict.** NVIDIA ships this profile as **two cooperating systems**: [NemoClaw](https://github.com/NVIDIA/NemoClaw) is a thin orchestration plane (host CLI + per-agent integration layer + versioned, digest-pinned **blueprint**) that packages supported agent runtimes (OpenClaw default, Hermes, LangChain Deep Agents Code); [NemoClaw Community](https://github.com/NVIDIA/nemoclaw-community) describes the composition as Model + Harness + OpenShell, where OpenShell is "the sandbox, gateway, policy, provider, and networking substrate." [OpenShell](https://github.com/NVIDIA/OpenShell) (Rust) is the actual control/enforcement product: a gateway control plane, pluggable compute drivers (Docker/Podman/MicroVM/Kubernetes), a two-trust-level sandbox whose **in-sandbox supervisor + policy proxy** enforce deny-by-default egress at syscall/socket/L7 level, and **gateway-held credential custody** with placeholder substitution at the egress boundary. The decisive contrast with DSH: this stack enforces **below the tool-call abstraction** — on every outbound byte and every file path via Landlock/seccomp/netns plus an L7 proxy (REST/WebSocket/GraphQL/**MCP method-and-tool rules**) — while DSH enforces at the guarded tool pipeline and process-spawn layer. Consequently almost everything downstream of "network egress control" (network approvals, policy tiers/presets, MCP-L7 policy, key-injection-at-boundary, denial-driven rule authoring) is **absent or differently enforced in DSH**, while conversely DSH's event-sourced log, tool-argument guards, seam-based composition, and cross-platform runners have no counterpart here. Neither system wraps the other's category: NemoClaw's agent-harness content (skills/persona/loop) belongs entirely to the wrapped agents; NemoClaw contributes lifecycle, custody, policy packaging, and inference wiring around them.

## 1. Positioning and layer ownership

| Control | NemoClaw (orchestration) | OpenShell (substrate) |
|---|---|---|
| Sandbox lifecycle | onboard/probe/rebuild/recover/snapshot/upgrade reconciliation; records lifecycle state; refuses on failed admission checks | gateway issues create/delete via compute drivers; supervisor manages in-workload startup, policy load, terminal-state reporting |
| Policy definition/packaging | versioned blueprint + baseline policy + maintained presets + tier chooser (Balanced/Open/Personal); posture profiles (docs) | declarative YAML policy schema; static (fs/process) locked at creation, dynamic (network/inference) hot-reloadable; OPA-engine evaluation in-sandbox |
| Credential custody | never persists keys to disk (~/.nemoclaw is 0700 non-secret); registers values with gateway in-memory-only during onboard | sole system of record: gateway store + pluggable credential drivers (encrypted DB default, Vault/K8s Secrets/DB credstore); placeholders resolved only at approved egress |
| Inference routing | provider validation/model choice; writes matching route refs into agent config; managed local-inference catalogs (vLLM/llama.cpp recipes, presets per DGX/Spark/Station) | `https://inference.local` interception: TLS terminate with sandbox CA → strip caller creds → forward via `openshell-router` using gateway-resolved route bundle |
| Integrations/MCP | managed-MCP commands (add/remove, Streamable HTTP, credential-name metadata), messaging-channel manifests (Slack/Discord/Teams/Telegram/WhatsApp/WeChat/GChat) | provider objects + generated endpointless profiles (e.g. `nemoclaw-mcp-v1`) bound by generated L7 policies; placeholder substitution at boundary |
| Remote operation | tokenized dashboard URLs, port-forward lifecycle, CLI guidance | outbound supervisor relay (no inbound ports): SSH/exec/tar file-sync/TCP-forward; browser service routing via wildcard DNS SAN |

## 2. Architecture profile

### 2.1 Sandbox lifecycle
Blueprint pipeline: **Resolve → Verify (digest) → Plan → Apply (via `openshell` CLI) → Status**. `blueprint.yaml` pins the sandbox image by sha256 digest (`ghcr.io/nvidia/openshell-community/sandboxes/openclaw@sha256:b3d83…`), mirrors that digest into a top-level `digest:` field so image bumps can't skip verification (issue #1438), and pins compatible `min/max_openshell_version` + `min_openclaw_version` — an interlocking supply-chain posture `[NC] nemoclaw-blueprint/blueprint.yaml`. Code enforces digests past apply-time: snapshot restores compare the current blueprint digest to the recorded one and refuse mismatches (`nemoclaw/src/commands/migration-state.ts:965–992`), and policy transitions carry a durable `target_policy_digest` checked before application (`src/blueprint/runner.ts:2577`). Onboarding runs a read-only `host probe` readiness report (capabilities, qualifications, findings, evidence, provenance) then applies admission checks before effects; progress is checkpointed so interruptions resume `[NC] docs/about/how-it-works.mdx`. Lifecycle verbs preserve state deliberately: stop keeps workspace/policies/registry; rebuild recreates the container from recorded metadata restoring **manifest-declared** state only (credential-bearing files excluded per agent); uninstall preserves backups unless `--destroy-user-data`. Underneath, OpenShell declares main-process exit (including exit 0) a terminal `Error` state with normalized exit codes persisted, restart policies must not resurrect it, and supervisor JWTs are renewed in memory while the sandbox record exists `[OS] architecture/gateway.md, sandbox.md`.

### 2.2 Policy enforcement
Four declared domains with a static/dynamic split: **Filesystem** (Landlock) and **Process** locked at creation; **Network** and **Inference** hot-reloadable via `openshell policy set` `[OS] README.md` protection-layers table. Enforcement physically happens **inside each sandbox**: "The gateway does not enforce agent network policy at request time. That happens inside each sandbox, where the supervisor and proxy can observe local process identity" `[OS] architecture/gateway.md` (the published best-practices table saying "Network → gateway" is doc drift — see §6). The shipped NemoClaw baseline policy shows the shape: deny-by-default comment; `filesystem_policy.read_only` covering `/usr,/lib,/proc,/app,/etc,/var/log,/var/lib/dpkg,/dev/urandom` + managed CA/env files; `landlock: compatibility: best_effort` with an explicit TODO that enforce mode is deferred (#516); `process.run_as_user: sandbox`; network endpoints carrying protocol, method/path allow-rules and per-endpoint `binaries` allowlists (TOFU binary identity) `[NC] nemoclaw-blueprint/policies/openclaw-sandbox.yaml`. Dynamic reloads acknowledge revisions (LOADED/FAILED, hash-based identity), keep last-known-good on poll failure, and can never partially activate: invalid combined updates preserve the previous runtime pair `[OS] architecture/sandbox.md`. Product packaging on top: maintained presets (npm, pypi, huggingface, brew, brave/tavily, github, gmail, outlook, jira, slack…) applied via `nemoclaw <name> policy add <preset>` and recorded into rebuild state; onboard tiers Balanced/Open/Personal (Personal forces a hostless L4 allow-all-80/443 that docs themselves flag as exfiltration-prone); risk framework + four posture profiles (Locked-Down default … Personal) in Security Best Practices. Operator interaction: denied requests surface in the TUI for approve/deny; grants persist within the sandbox instance but not the baseline file; denied L4 CONNECTs flow through a mechanistic mapper into pending `NetworkPolicyRule` proposals (`openshell rule get --status pending`), while L7 denials hand the agent structured 403 context so **the agent itself authors the narrowest rule** `[OS] architecture/sandbox.md`; NemoClaw even documents an "explain network policy to agents" page and instructs its runtime-context block to try allowed actions first and attribute failure causes `[NC]`.

### 2.3 Credential custody
"NemoClaw does not persist provider credentials to host disk. The OpenShell gateway is the only system of record for stored credentials," and `credentials list` exposes names only — "The CLI cannot read the values back" `[NC] docs/security/credential-storage.mdx`. Registration happens once at onboard (env value staged in process.env), then the value lives gateway-side; the supervisor injects resolved variables only into the initial agent process and SSH children, and driver-controlled environment overrides prevent template spoofing `[OS] architecture/sandbox.md`. Injection is **endpoint-bound**: static credentials resolve only when request host/port/path match the provider's effective profile; refresh swaps values atomically and revokes prior state on failure `[OS] architecture/sandbox.md, gateway.md`. Advanced custody machinery: pluggable credential drivers with opaque handles (default server-owned encrypted SQLite/Postgres storage, optional Vault/Kubernetes-Secrets/DB-credstore); OAuth refresh brokering with bounded error classification; SPIFFE Workload-API dynamic token grants (`client_credentials` via supervisor SVID, gateway-brokered `token_exchange`); AWS SigV4 re-signing; a GCP loopback metadata server for SDKs bypassing the proxy; reserved placeholder namespaces; interceptor-facing protobuf secret fields elided recursively so middleware cannot observe injected material `[OS] architecture/gateway.md, sandbox.md`. NemoClaw adds app-level belt-and-braces: onboarding refuses success if raw search keys are visible in the live sandbox env or the isolation check fails; Hermes startup rejects raw secret-shaped values; Deep Agents launchers refuse upstream-auth state files; GitHub tokens are never persisted (delegated to `gh auth token` per-run staging); legacy plaintext stores are migrated only after verified gateway registration, then shredded; managed-MCP stores name/ownership metadata only, with the raw bearer value gateway-held behind an `openshell:resolve:` placeholder written into agent config.

### 2.4 Inference routing
The agent always calls `https://inference.local`, which bypasses ordinary (OPA) network policy and follows a dedicated path: sandbox-CA TLS termination → detection of OpenAI/Anthropic-compatible shapes → strip caller-supplied credentials/disallowed headers → forward through `openshell-router` with a `GetInferenceBundle` route bundle the gateway resolves (endpoint URL, protocol, auth style, route shaping incl. Vertex-AI `model_in_path`/`:rawPredict` handling). Non-`inference.local` external endpoints are ordinary traffic needing policy `[OS] architecture/sandbox.md, gateway.md`. NemoClaw curates provider profiles in the blueprint (default NVIDIA NIM `integrate.api.nvidia.com`, NCP with dynamic endpoint, in-cluster nim-local, vLLM localhost with dummy credential, routed→localhost:4000) and validates provider+model at onboard before writing references into the managed agent configuration; switching models/providers at runtime updates route plus config consistently `[NC] blueprint.yaml`. The `routed` profile enables a distinctive extra: **complexity-based cost routing** via NVIDIA's LLM Router v3 — a Qwen3.5-0.8B encoder predicts per-model P(correct), and the router picks the cheapest model within a tolerance (default 0.20 accuracy-percentage-point loss for cheaper models) using per-model cost weights `[NC] nemoclaw-blueprint/router/pool-config.yaml`. For local fleets, `managed-inference/` ships vLLM/llama.cpp images (with a Go request-guard sidecar), model YAMLs, per-hardware recipes/presets/qualifications, and opt-in experimental GPU passthrough (CDI/`--gpus` fallback).

### 2.5 Managed integrations / MCP
Managed MCP supports authenticated HTTPS Streamable-HTTP MCP servers across all three agents: NemoClaw stores credential-name/ownership metadata, OpenShell stores the raw value outside the sandbox, and the adapter receives a placeholder replaced only at the approved egress boundary; the OpenShell proxy can additionally evaluate **MCP-specific L7 rules — method, tool, and supported params matchers on `tools/call` bodies**, with spec-recommended tool-name syntax checking by default (`mcp.strict_tool_names` opt-out) and generic JSON-RPC method rules `[OS] architecture/sandbox.md`; responses/SSE streams are relayed but not yet parsed. The blueprint requires exactly this support (`Requires OpenShell MCP/JSON-RPC L7 policy support from NVIDIA/OpenShell#1865`) and vendors an endpointless provider profile (`nemoclaw-mcp-v1`, credentials bound by generated MCP policies) `[NC]`. Provider/collision safety: before a rebuild mutates managed-MCP state, credential-key collisions across attached providers stop the operation without deleting anything `[NC] credential-storage.mdx`. Messaging integrations ship as channel manifests with credential delivery + network policy per channel (Slack, Discord, Teams, Telegram, Google Chat, WeChat, WhatsApp), with a documented exception that QR-paired WhatsApp retains declared session credentials inside the sandbox so lifecycle ops can preserve them.

### 2.6 Filesystem / network boundaries
Isolation is layered, not primitive: Landlock path policy + non-root drop with **capability bounding set cleared during privilege drop** (spawn aborts unless the set ends empty) + seccomp blocking raw-socket syscalls that would bypass the proxy + network namespace forcing ordinary egress through the local CONNECT proxy + the policy proxy evaluating destination, binary identity (TOFU), TLS/L7 rules, SSRF checks, and inference interception `[OS] architecture/sandbox.md`. Anti-evasion details reach unusual depth: epoch-scoped synthetic DNS addresses invalidated across restarts; nftables DNAT fencing that admits traffic only when kernel-recorded as redirected; transparent-TCP policies rejected at creation rather than partially activated; corporate-upstream CONNECT chaining that is fail-closed (invalid proxy settings are fatal at startup, workload `HTTP(S)_PROXY` vars ignored/rewritten), port/resolution-aware NO_PROXY, and intercepting-proxy CA folding `[OS] architecture/sandbox.md`. SSRF hygiene on the NemoClaw side: catch-all hosts, `allowed_ips` widening in user presets, and loopback/link-local/cloud-metadata ranges blocked; onboarding validates endpoints with IP+DNS checks and pins resolved IPs to defeat DNS rebinding; wildcard scoping is allowed but bounded (`*.example.com`) `[NC]`.

### 2.7 Remote operation
Control is inbound-free: sandboxes maintain **outbound** supervisor sessions, and the gateway opens per-request byte relays (`ConnectSupervisor`/`RelayStream`/`ForwardTcp`) for interactive SSH (incl. attachment to the canonical main process with PTY replay), command exec, tar file sync, and TCP forwarding restricted to loopback targets inside the sandbox `[OS] architecture/gateway.md`. Browser access to in-sandbox services rides host-based routing (`sandbox--service.<routing-domain>` derived from wildcard DNS SANs; `openshell.localhost` loopback default) with Fetch-Metadata/Origin/Referer cross-origin rejection on the plaintext loopback path `[OS] architecture/gateway.md`. NemoClaw wraps this as operator UX: background port-forwards to the dashboard (default 18789, auto-scan upward), tokenized dashboard URLs (`#token=…`, regenerated per container start), Bearer-token API auth (401 unauthenticated), and refusal to bind gateways to `0.0.0.0` while JWT auth is active; headless-server docs print copyable SSH tunnel commands and keep gateways loopback-only `[NC] docs`. The k9s-style TUI (`openshell term`, 2-second auto-refresh) owns live network activity and the approval queue.

### 2.8 Deployment controls
Installers are curl|bash (normal user, nvm+npm; Node ≥22.16, npm ≥10, Docker prerequisite); express-install presets per platform accept recommended settings; platform matrix is Linux/DGX-Spark-primary, DGX Station tested-with-limitations, macOS Apple Silicon via Colima limited, Intel Mac unsupported, WSL2 limited with Docker Desktop qualified, Windows-ARM GPU denylisted; GPU passthrough is off-by-default and explicitly not CI-tested on Spark `[NC] README/docs/platform-support`. Updates re-run the installer following an admin-promoted `lkg` tag (`NEMOCLAW_INSTALL_TAG` override), demand fresh backups of registered sandboxes, then reconcile stale sandboxes via `upgrade-sandboxes --check/--auto` — bypass paths like `openshell self-update` on managed installs are warned against. Gateway PKI bootstraps idempotently (`generate-certs`), via Helm hook Job or cert-manager or systemd ExecStartPre; Kubernetes adds projected-SA→gateway-JWT exchange validated with TokenReview + pod ownerReference checks `[OS] architecture/gateway.md`. Multi-user posture: mTLS/OIDC/Cloudflare-JWT client auth, workspace RBAC, gRPC rate limits, optimistic-concurrency persistence with compile-time-enforced CAS writes (`put`/`put_message` are `#[cfg(test)]`-gated) `[OS] architecture/gateway.md`. Telemetry: anonymous aggregate categories only, disabled by env or compiled out entirely (`--no-default-features` drops emission code), aggregate reports published biweekly `[OS] README.md`; no NemoClaw-specific statement was found first-party (§7).

## 3. Distinctive design decisions

1. **Enforcement below the tool abstraction.** Guards live in the kernel and the proxy path (syscall/socket/L7/MCP-body), invisible to and unbypassable-by wrapped agent configs — the inverse bet from DSH's guarded tool pipeline, where frozen arguments and event waterfalls give rich semantics but bytes-level egress escapes policy entirely.
2. **Two trust levels per workload.** Root supervisor prepares isolation, runs proxy/SSH/relay, injects creds; the agent child drops privileges with an emptied capability bounding set — fail-closed spawn.
3. **Digests everywhere.** Image digest pinning mirrored top-level, verify-before-apply, digest-guarded snapshot restores, durable `target_policy_digest` on transitions — supply-chain posture as first-class artifact mechanics.
4. **The agent as policy actor.** Structured denial payloads invite the agent to author narrowest L7 rules; pending proposals enter an operator queue; docs teach agents to phrase failures by cause. Enforcement and model behavior form an explicit feedback loop.
5. **Custody by indirection.** Keys exist only gateway-side behind opaque handles/endpoints; sandboxes see placeholders that resolve per-request post-admission; SDK identities brokered through SPIFFE; middleware literally cannot observe annotated secret fields.
6. **Artifact-governed composition.** The blueprint (not plugins, not prompts) is the distributable unit of desired end-state, versioned independently with inter-repo compatibility pins — closer to a Helm chart than a plugin registry.
7. **Documented TCB.** `docs/security/tcb-boundary.mdx` enumerates trusted/untrusted components and review invariants (nonce-bound privileged helpers, descriptor-rooted FS ops, transition locks, pidfd signaling) — a security-engineering transparency practice neither DSH nor most harnesses attempt.

Absence is data, both directions. What **this stack lacks** that DSH ships: append-only event-sourced session log as single source of truth (relays/logs/status here are operational streams, not a reconstructable record); tool-argument-level guards and approval waterfall (arbitrary JSON schemas, monotonic deny-only guards, auditable `approval/*` pairs); seam-declared composition with reversibility guarantees (blueprint applies containers, not composable services); skills/instruction-plane features (progressive disclosure, plan mode, KV-cache discipline), Code Mode, workflow/subagent/goal machinery — all delegated to whichever claw the blueprint wraps; Windows/macOS-native confinement (host matrix is effectively Linux-container-only); npm-scale plugin distribution; lightweight single-process footprint. Conversely the network-and-custody envelope above is what DSH has no story for today.
