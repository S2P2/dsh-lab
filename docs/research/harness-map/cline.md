# Cline: architecture & distinctive capabilities (vs DSH baseline)

**Baseline for: Agent Harness Capability Map (profile #18 of 18)**

- **Researched:** 2026-08-28 (session clock). **Subject:** Cline (github.com/cline/cline), open-source Apache-2.0 coding agent — source-inspectable monorepo.
- **Pinned:** cline/cline `main` @ `aa4753f4abc8303dcecd5d27cde622215047c21b` (HEAD at research time via `git ls-remote`; full tree from codeload tarball at that SHA). Extension package `claude-dev` / publisher `saoudrizwan` / **v4.1.16** (`apps/vscode/package.json`).
- **Evidence tiers:** **[src]** repo paths below at the pinned SHA; **[arch]** `sdk/ARCHITECTURE.md` (self-declared "architecture source of truth", 833 lines, read in full); **[docs]** official docs fetched 2026-08-28 as raw markdown from `docs.cline.bot` (index via `llms.txt`; pages cited inline). Inference marked ⚠️.
- **Acquisition note:** git checkout machinery unusable in this sandbox (msys `sh` spawn denied) — read via codeload tarball + Node `fetch` for docs; all citations are paths within the extracted pinned tree.
- **DSH comparison:** `dsh-baseline.md` pinned `b150a55`; §7 taxonomy D1–D20, capability names verbatim. Labels: **Equivalent / Packaging gap / Plugin opportunity / Core gap / Not applicable**.

**Verdict.** Cline is mid-migration from "one fat VS Code extension" to a **multi-host agent platform**: a published four-package SDK (`@cline/shared|llms|agents|core`, `sdk/ARCHITECTURE.md`) whose stateless loop + stateful core runs identically inside VS Code, an OpenTUI CLI, a Tauri desktop app, and — most distinctively — a **detached local hub daemon** that owns sessions so CLI, desktop, and browser clients can attach/detach from the same authority runtime [arch §Hub-Backed Runtime]. Three choices matter most against DSH. (1) **The editor is a typed RPC periphery, not the runtime**: the webview↔extension and extension↔host boundaries are both generated gRPC (`apps/vscode/proto/cline/*.proto` — 18 services; `proto/host/*` — 6), and the extension bootstraps SDK sessions through `src/sdk/cline-session-factory.ts` while contributing host executors (terminal, diff-view edits, file-read) via `vscode-runtime-builder.ts` — Cline architecturally solved the editor-vs-runtime separation this map keeps asking about, then went further with editor-agnostic ACP and a desktop host. (2) **Hub-owned durable automation**: cron specs, event-driven specs, a revision-gated agenda task queue, and chat-platform **connectors** (Telegram/Slack/Discord/Google Chat/WhatsApp/Linear) all run in the daemon [arch §Agenda, §CronService; docs cli/connectors.md] — the D9/D10 territory DSH declares absent. (3) **Permissions as per-tool policy data**: `{enabled, autoApprove}` per tool name plus `"*"` wildcard, presets `default|yolo`, modes `act|plan|yolo|zen`, plan mode enforced by a **command-guard hook** that hard-blocks file-editing shell commands [src `extensions/tools/presets.ts`, `command-guard-extension.ts`] — persisted structured policy where DSH ships one-shot-only approvals plus preset bundling. Meanwhile Cline is *removing* its once-signature browser automation from the SDK task path (`src/sdk/task-proxy.ts`: "browser automation removed in this migration") and checkpoints moved to per-run git-stash refs — convergence in the opposite direction of DSH's own absences.

## 1. Monorepo & runtime architecture [src; arch]

- **Layout:** `sdk/` packages — `shared` (contracts, hook engine, extension registry, prompt + remote-config schemas), `llms` (provider settings/config, model catalogs + manifests, gateway registry, AI-SDK-backed execution), `agents` ("stateless runtime loop, tool orchestration, event emission"), `core` ("stateful orchestration": sessions, storage, config watching, plugin loading, default tools, compaction policy, telemetry, hub services) — plus internal `ui`, and apps `vscode` / `cli` (OpenTUI) / `cline-hub` (web dashboard + Kanban) / `examples/desktop-app` (Tauri `@cline/code`) [arch §Layered Model].
- **Hard boundary:** `agents` stays stateless (no session persistence, provider settings storage, RPC lifecycle, host approvals); `core` stays generic (no org/provider-specific behavior); one-way optional layers [arch §Architectural Constraints].
- **Execution boundary:** one `RuntimeHost` interface — `LocalRuntimeHost` (in-process), `HubRuntimeHost` (shared local hub), `RemoteRuntimeHost` (explicit endpoint) — selected in `packages/core/src/runtime/host.ts`; the `ClineCore` facade never branches on local-vs-hub [arch §Design Seams 3].
- **Hub daemon:** auto-spawned detached process per workspace; WebSocket server; discovery record carries a per-process auth token (constant-time validated, owner-only file perms; sent via `Sec-WebSocket-Protocol` / bearer header, never endpoint URLs); build fingerprint + epoch identity retire-and-replace stale daemons so concurrent installs converge on the newest build [arch].
- **Multi-client sessions:** hosts attach/detach from the shared authority runtime without stopping it; `run.started` correlates by `requestId`/`clientId`; session status is "reported, never fabricated" — each turn owns its `running` → `idle` transition [arch]. Client adapters: `NodeHubClient`, `HubSessionClient`, `HubUIClient`, `connectToHub` [arch].
- **Session persistence is lazy:** id allocated at start, DB row/messages artifact only on first accepted user turn; canonical history = full-fidelity messages artifact; root vs aggregate (root+teammates) usage buckets [arch].
- **CLI startup discipline:** first TUI frame must not wait on hub spawn; compatible hub reused under `backendMode: "auto"`, else falls back to local runtime; resume hydration deferred until after first paint [arch §Interactive CLI Startup].
- **Composition contrast:** extension points are *repeated seams* — file watchers for rules/workflows/skills/agents/hooks/plugins, `DefaultRuntimeBuilder` generic inputs, hook arrays — not DSH's service-resolution DI. ⚠️ Inference: functionally similar "swap at a named seam" culture without a kernel or patch layering.

## 2. Agent loop, tools, permissions

- **Loop:** `AgentRuntime` (`sdk/packages/agents/src/agent-runtime.ts`, ~2.2k lines): run → per-iteration model call → stream events (`run-started`, text/reasoning deltas, tool started/update/finished, agent done) → tool execution → append [src L468+, L708-940].
- **Hook arrays:** `beforeRun / afterRun / beforeModel / afterModel / beforeTool / afterTool / onEvent` [src L640-646]; `beforeTool` can override the tool's `policy` (approval decision) [src L1710-1751]; hooks return `appendContext` blocks injected into the turn [src L484].
- **`prepareTurn` seam:** core-injected turn-preparation pipeline (compaction owner); context-window overflow forces a compaction pass through it and retries the request [src L956-976; arch §Seams 9].
- **SDK built-in tools:** `read_files, search_codebase, run_commands, apply_patch, editor, skills, ask_question, submit_and_exit` (the `attempt_completion` analog), optional `fetch_web_content`, plus `spawn_agent`, ~17 `team_*` tools, and a `tasks` agenda tool (currently flag-disabled) [src `extensions/tools/definitions.ts`, `team/team-tools.ts`; arch §Agenda]. ⚠️ Docs use short names (`bash`, `search`, `fetch_web`) [docs tools-reference/all-cline-tools.md].
- **Model-conditional tool routing:** `model-tool-routing.ts` — "openai-native-use-apply-patch", "codex-and-gpt-use-apply-patch", "claude-editor-off" — the tool *schema set itself* varies by model family; the deliberate inverse of DSH's KV-cache-stable catalog discipline.
- **Modes:** `act | plan | yolo | zen` [src `shared/src/session/runtime-config.ts`]; mode rides both the system-prompt build and per-message `<user_input mode="…">` tags with `<mode_notice>` transition markers [src `shared/src/prompt/cline.ts` L23].
- **Plan preset:** read-only tool set that *keeps shell for investigation*, while the plan-mode **command-guard hook** registered by the runtime builder hard-blocks file-editing commands [src `presets.ts` L39-57, `command-guard-extension.ts`].
- **ToolPolicy:** per-tool `{ enabled?, autoApprove? }` + `"*"` wildcard default; presets `default | yolo` [src `presets.ts` L133-148]; schedules marked `unattended` inherit `autoApproveTools` explicitly, and agents can never self-approve agenda work [arch §Agenda; src `hub-server-transport.ts` L463-510].
- **Extension-side approval surface:** classic per-category Auto Approve (read/edit project vs all files, execute safe vs all commands, browser, MCP; legacy `maxRequests` default 20) maps onto SDK policies via `sdk/sdk-tool-policies.ts`; OS notifications on approval-needed and on 30s-running auto-approved commands [docs features/auto-approve.md; src `shared/AutoApprovalSettings.ts`].
- **No guarded pipeline:** nothing matching DSH's pre/around/post waterfall with frozen arguments — policy resolution, hooks, and executor run in one path [src `agent-runtime.ts`]. ⚠️ Absence read from code layout, not an exhaustive audit.

## 3. Checkpoints & editor/VS Code integration

- **Checkpoints (SDK):** per-user-run git checkpoints *inside the workspace repo* — stash refs tagged `cline checkpoint session=`, metadata `{latest, history[]}` (ref/createdAt/runCount/kind stash|commit) in session metadata, custom `createCheckpoint` injection point [src `core/src/hooks/checkpoint-hooks.ts`; `session/checkpoint-restore.ts`, `checkpoint-diff.ts`].
- **Docs-vs-source drift:** official docs still describe the classic separate **shadow Git repo** committed after every tool use, enabled by default [docs core-workflows/checkpoints.md]; the VS Code extension keeps only UI/restore glue (`core/controller/checkpoints/*`, `sdk/sdk-checkpoints.ts`) — implementation clearly in transition at this SHA.
- **Webview↔extension = generated gRPC:** 18 `cline.*` services — account, browser, checkpoints, commands, common, file, hooks, marketplace, mcp, models, oca_account, remote_config, slash, state, task, ui, web, worktree [src `apps/vscode/proto/cline/`].
- **Extension↔host = inverted hostbridge:** `proto/host/{window,diff,env,workspace,core_connection,testing}.proto` behind `HostProvider`; `hosts/external/` re-implements the same host services for non-VS Code embedding [src `hosts/vscode/hostbridge-grpc-service.ts`, `hosts/external/`].
- **Editor-native mechanics stay host-side:** `VscodeTerminalManager/Process/Registry` with shell-integration OSC-633 parsing + prompt heuristics + execution modes [src `hosts/vscode/terminal/`]; streaming edits rendered in the diff view via `sdk-diff-edit-coordinator.ts` + `VscodeEditPreview.ts`; `vscode-file-read-executor.ts` / `vscode-run-commands-tool.ts` contributed as session executors [src `sdk/`].
- **Legacy compatibility:** classic task dirs under `~/.cline/data/tasks/` still read via `legacy-state-reader.ts` / `legacy-task-handling.ts` [src `sdk/`].
- **Worktrees as product surface:** full proto service — create/delete/merge/switch/branch-list + `.worktreeinclude` [src `core/controller/worktree/`]; **Kanban** app runs parallel agents in isolated worktrees [docs usage/kanban.md]. CI: GitHub Actions samples for @cline issue triage and PR review [docs cli/samples/].

## 4. Browser / computer use / web fetch

- **Browser automation is being retired from the agent path:** `sdk/task-proxy.ts` L30-32 — "Browser session — stubbed (**browser automation removed in this migration**)" [src].
- **Remnants:** `BrowserSession` / `BrowserDiscovery` (puppeteer-core + chrome-launcher, remote Chrome on debug port 9222, webp screenshots) remain in-tree; `browser_action` survives only in legacy message enums, prompts, and the docs' stale auto-approve category [src `services/browser/`].
- **D12 net:** at this SHA both Cline and DSH effectively lack live browser automation; computer use absent in both — absence is data both ways.
- **Web fetch ships enabled:** SDK `fetch_web_content` (HTML→markdown) plus `UrlContentFetcher` for @-URL mentions [src `SdkController.ts` L43] — vs DSH `web_fetch` shipped **disabled** pending SSRF policy.

## 5. MCP, rules/workflows/skills, plugins & hooks

- **MCP client:** official `@modelcontextprotocol/sdk` — stdio + SSE + streamable-HTTP transports; chokidar-watched `.cline/mcp.json` with env-var expansion; per-server timeout min/max; **OAuth manager**; reconnect handler; and tools **plus prompts and resources/templates** surfaced [src `services/mcp/McpHub.ts` (2.2k lines), `McpOAuthManager.ts`, `schemas.ts`].
- **Marketplace:** `proto/cline/marketplace.proto` + `controller/marketplace/` for server/tool discovery [src].
- **Rules/workflows/skills:** one unified file watcher loads Markdown+YAML frontmatter configs from global and workspace `.cline/` trees (and `AGENTS.md` rules) with per-file `disabled` toggles and plugin-skill merging [src `extensions/config/user-instruction-config-loader.ts`, `unified-config-file-watcher.ts`].
- **Workflows** = slash-invocable markdown prompt scripts; **remote config materializes org-managed rules/workflows/skills into workspace `.cline/<plugin>/`** [arch §Remote-Config-Managed Runtime]. `.clineignore` deprecated [docs customization/clineignore.md].
- **Plugins:** `AgentPlugin` contract — register tools/extensions, declare `automationEvents`; executed in **sandboxed session-local subprocesses**: idle-evicted after 30 min (`CLINE_PLUGIN_IDLE_TIMEOUT_MS`), generation-aware pending requests, parent-IPC exit, count scales with active sessions [arch §Seams 8/10]. Install sources: file/URL/npm/git/local [docs sdk/plugin-install.md].
- **Hooks** = lifecycle interception contract in `shared/src/hooks`; docs route users to the SDK plugins page [docs customization/hooks.md].
- **No UI extensibility:** plugins have no webview/slot surface — the webview is a closed first-party React app (DSH's `ctx.slots` + client bundles are stronger here). ⚠️ Absence inference from plugin docs + repo layout.

## 6. Task/session state, context, telemetry, multi-agent, automation, channels

- **Session state:** SQLite stores behind storage adapters [arch §Seams 7]; session snapshot + versioning service; display-vs-canonical message split; `history-origin` records client `source` (`vscode|desktop|cli|core`) separately from initiation `mode` (`user|automation|subagent|team`) [src `core/src/session/`; arch].
- **Multi-agent:** `spawn_agent` subagents, delegated agents, yaml-defined **configured agents**, and shipped agent teams — mailbox, mission log, runs, outcome fragments (`team_send_message`, `team_broadcast`, `team_create_outcome`, `team_finalize_outcome`, …) [src `extensions/tools/team/team-tools.ts`; docs cli/agent-teams.md]. Parallel research subagents marketed as main-context protection [docs features/subagents.md].
- **Cron automation:** Markdown specs (`one_off|schedule|event`) under global `~/.cline/cron/` or workspace `.cline/cron/`; SQLite `cron.db`; watcher→reconciler→materializer→runner with atomic claim/renew; timezone-aware catch-up; event envelopes with dedupe/debounce/cooldown; per-run Markdown reports [arch §CronService].
- **Agenda queue:** durable proposed tasks (`~/.cline/tasks/*.task.md` + SQLite truth), every new task `pending_approval`, approval bound to exact `revision`, fail-closed spec reconciliation, `manual|auto_start|unattended` automation policy with concurrency/chain-depth/hourly guardrails; `tasks` tool cannot self-approve [arch §Agenda].
- **Channels:** **connectors** turn Telegram/Slack/Discord/Google Chat/WhatsApp/Linear into session ingress (`cline connect` wizard; webhook signing secrets etc.; CLI-only) [docs cli/connectors.md]; **ACP** embeds the CLI in Zed/JetBrains/Neovim/Emacs [docs usage/acp.md]; OpenTUI CLI, VS Code, Tauri desktop, Kanban web with remote-access guidance [docs kanban/remote-access.md].
- **Enterprise:** WorkOS SSO, remote provider configuration, self-hosted mode suppresses PostHog [src `TelemetryProviderFactory.ts` L104; docs enterprise-solutions/].
- **Telemetry:** provider interface with **PostHog product analytics + OpenTelemetry** implementations; levels `all|off|error|crash`; respects VS Code global telemetry; device/distinct ids; opt-in/out [src `services/telemetry/`]. Contrast DSH: OTel-only, default-off, redaction waterfall — Cline's default follows VS Code (on), a weaker local-first stance.
- **Memory (D7):** no built-in cross-session memory; **Memory Bank** is a documented methodology implemented as user-authored rules files (`projectbrief.md`, `activeContext.md`, …) [docs best-practices/memory-bank.md] — same reach as DSH's AGENTS.md/skills; absence is data in both.

## 8. Uncertainties

1. **Browser tooling fate** — stubbed in the SDK task path at this SHA, still in-tree and in docs; whether `browser_action` returns (desktop/CLI only?) is unresolved; docs pages lag the code.
2. **Checkpoints mechanism** — docs describe a shadow repo; SDK implements workspace-repo stash refs; which path the shipped VS Code build takes (the old extension `CheckpointTracker` is gone) is inferred, not runtime-verified.
3. **`zen` mode** — appears in mode enums and CLI/hub flags; behavioral definition not located; left undescribed deliberately.
4. **Legacy residue** — repo is mid-migration; some `core/controller` services (marketplace, oca_account, slash) may be legacy-only. Paths are real at the pinned SHA; dead-code status unaudited.
5. **Docs-vs-code tool-name drift** (`bash`/`run_commands`, `search`/`search_codebase`, `fetch_web`/`fetch_web_content`) — live model-facing schema names may match neither exactly.
6. **Velocity** — v4.1.16 moves weekly; re-pin before any external citation.
