# pi (badlogic/pi-mono → earendil-works): minimal LLM abstraction + agent core + coding agent — architecture & capability surface

**Baseline for:** Agent Harness Capability Map (profile #14 of 18)

**Verdict.** Pi is the strongest single-seam counter-thesis to DSH in the corpus: where DSH decomposes a harness into ~50 config-composable capability seams, pi ships a deliberately tiny loop (718 LOC) plus **one deep extension seam** — a jiti-loaded TypeScript module with ~30 API methods and ~40 pipeline-wide event hooks — and pushes every product feature DSH holds in core (subagents, plan mode, permission gates, todos, MCP, background bash) *out* into extensions, packages, or OS-level containerization. The mono-repo also turns out to be DSH's own substrate: DSH's dormant multi-provider adapter `dsh-llm-pi-ai` wraps `@earendil-works/pi-ai`, so this profile's subject supplies DSH's provider portability today. Most revealing is pi's in-flight `AgentHarness` rewrite — `ExecutionEnv` (FileSystem+Shell capability interfaces), a single-writer record log with a corruption taxonomy, replay-marked tools, suspended/deferred runs, conformance suites — a "minimal" harness independently converging on DSH's seams/event-sourcing/replay decomposition once it needs remote protocols and crash recovery. Pi's session model branches in place (JSONL tree + LLM branch summaries) where DSH forks copies; its extension trust model is an input-loading gate, not a sandbox; and its client/server boundary is a strict CBOR snapshot-authoritative protocol with leases. For DSH, pi is evidence that one rich programmatic seam can substitute for much of a composition grammar — and that the capabilities pi keeps *reaching for* (durable replay, same-world execution envs, wire conformance) are the ones DSH already productized.

## Architecture profile

### 1. Repo shape, scale, and the two-generation core (D1)

- **Identity:** TypeScript npm mono-repo, lockstep-versioned (all packages share one version, `minor` = breaking), MIT, Node ≥22.19, built with `tsgo`/Biome; standalone Bun binaries per release. Project renamed "Pi Agent Harness"; npm scope migrated `@mariozechner/*` → `@earendil-works/*` (extension loader still aliases the old scope). Author org: Earendil Works (Mario Zechner); RFCs live at rfc.earendil.com [src: README.md, AGENTS.md, packages/coding-agent/src/core/extensions/loader.ts:57-67].
- **Packages (src LOC measured on clone, tests/examples excluded):** `ai` 24.8k (186 files) · `agent` 11.7k (53) · `coding-agent` 54.5k (207) · `tui` 15.0k · `server` 2.1k · `session-backends` 2.2k · `protocol` 1.1k · `client` 1.1k · `evals` 1.2k · `telemetry` 0.8k. Build order encodes the dependency chain: tui → telemetry → ai → agent → session-backends/sqlite-node → protocol → client → server → coding-agent [src: root package.json `build` script; measured].
- **Two generations coexist in `packages/agent`:** (1) the *production* path — low-level `agent-loop.ts` (718 LOC) + stateful `Agent` (528 LOC); the coding agent runs on this today (`core/agent-session.ts`, 3.0k LOC); (2) the *next-gen* `harness/` subsystem (~5.6k LOC: agent-harness 471… plus session/, reducer 620, compaction 765, env/nodejs 649, tools, skills, conformance 946) — `AgentHarness`, currently a typed skeleton whose operations throw `HarnessNotImplemented` (create/restore included); only the experimental server path consumes it (`coding-agent/src/server/create-harness.ts`) [src: agent/src/harness/agent-harness.ts:74-82,347-353; grep AgentHarness over coding-agent/src].
- **Scale audit vs claim:** "minimal core" is real per layer — the loop is 718 LOC, `Agent` 528 — but the shipped product surface is ≈105k src LOC; breadth lives in provider adapters (ai 24.8k incl. 9 wire-protocol implementations ~8.5k) and the TUI/interactive layer (≈16k). Like nanobot, "small core" is a claim about the loop, not the system [measured].

### 2. LLM abstraction: pi-ai (D5) — the layer DSH itself wraps

- **Provider = runtime unit** owning catalog + auth + stream behavior; a `Models` collection routes each request to the owning provider. ~34 built-in providers (incl. subscription endpoints: Claude Pro/Max, ChatGPT/Codex OAuth, GitHub Copilot, ZAI/Kimi/Qwen/Xiaomi token plans, China-region variants). Providers share **9 API implementations** (wire protocols): anthropic-messages, openai-completions, openai-responses, openai-codex-responses, azure-openai-responses, google-generative-ai, google-vertex, mistral-conversations, bedrock-converse-stream — plus **`pi-messages`, pi's own SSE protocol spoken by the Radius gateway** (server-side message rewrites report policy impact) [src: ai/README.md §Supported Providers; ai/src/api/pi-messages.ts:1-9].
- **Generated model catalog:** built-in model metadata is generated from live provider catalogs (`scripts/generate-models.ts`; `pi update --models` refreshes; release source archives snapshot it). Hand-written ai core ≈20.6k LOC [src: AGENTS.md rule 27; root package.json; measured].
- **Auth chain per provider:** stored credential (type-tagged, one per provider, `CredentialStore.modify` serialized RMW so OAuth refresh can't double-rotate) > env var > ambient (AWS profiles, gcloud ADC); OAuth flows for codex/copilot/anthropic/openrouter/xai/kimi/"radius"; explicit `apiKey` wins per request [src: ai/README.md §Auth].
- **Distinctive API-level capabilities:** TypeBox tool schemas with **constrained sampling** (`strict: 'prefer'|'require'` JSON-schema enforcement; OpenAI **Lark/regex grammar tools** for GPT-5+); **deferred responses** (`deferred?: boolean|{window:"15m"|"1h"|"24h"}`, `StopReason:"deferred"`, `fetchDeferred/cancelDeferred`); serializable `Context` enabling **mid-session cross-provider handoff**; separate `ImagesModels` surface (image generation); never-throw streams (errors ride the AssistantMessage); `transformHeaders`; `compat` flags per model (supportsDeveloperRole etc.); faux provider for tests [src: ai/README.md; ai/src/types.ts:227-438].
- **Load-bearing DSH fact:** DSH's dormant multi-provider adapter `dsh-llm-pi-ai` wraps `@earendil-works/pi-ai` (pinned 0.82.1 in `pnpm-workspace.yaml`; comment: fresh pi-ai releases "carry the model catalog updates that are the whole point"). Pi's version at pinned HEAD: 0.84.3. **This profile's subject is DSH's actual provider-portability layer** [src: deepseek-harness checkout pnpm-workspace.yaml:45-60, packages/bundle/base/cordis.patch.yml:88-96; pi clone package.json].

### 3. Agent core: loop semantics (D1/D3)

- **Two-layer core:** raw `agentLoop()/agentLoopContinue()` yield *observational* event streams (no barriers); the `Agent` class adds state (`AgentState`: systemPrompt/model/thinkingLevel/tools/messages + streamingMessage/pendingToolCalls/errorMessage) and treats assistant `message_end` as a **barrier before tool preflight** [src: agent/README.md §Low-Level API; agent/src/agent-loop.ts, agent.ts].
- **AgentMessage vs LLM Message split:** app-level message types (declaration-merged `CustomAgentMessages`, e.g. `notification`, plus coding-agent's bashExecution/custom/branchSummary/compactionSummary) flow through `transformContext() → convertToLlm()` — one conversion boundary so UI-only types never reach the model [src: agent/README.md §Core Concepts; coding-agent/src/core/messages.ts:70].
- **Steering & follow-up are first-class queues** with drain modes `"one-at-a-time"|"all"`: steering delivered after the current assistant turn's tool calls finish; follow-ups only when no tool calls or steering remain. Exposed consistently across Agent API, TUI keybindings (Enter vs Alt+Enter), extension `sendMessage(deliverAs)`, and RPC commands [src: agent/README.md; coding-agent README §Message Queue; docs/rpc.md].
- **Tool execution semantics:** default parallel — preflight sequential, execute concurrent, `tool_execution_end` in completion order but persisted toolResults in assistant source order; per-tool `executionMode:"sequential"` **escalates the whole batch**; `beforeToolCall` can block (+`terminate`), `afterToolCall` can patch results; **unanimous-only `terminate: true`** stops the loop only if every finalized result in the batch terminates; `shouldStopAfterTurn` hook (used for compaction) stops gracefully before queue polling [src: agent/README.md §prompt() Event Sequence].
- **Events:** 10 kinds (agent_start/end, turn_start/end, message_start/update/end, tool_execution_start/update/end) + `agent_settled` at the coding-agent layer (auto-retry/compaction/follow-up exhausted) [src: agent/README.md; docs/extensions.md §agent_start].

### 4. The next-gen harness (mid-flight; D1/D13/D19 direction)

- `AgentHarness` implements `AgentLane` (prompt/skill/promptFromTemplate/compact/navigateTree/resume/abort/steer/followUp/nextRun/cancelQueued/recordUsage/peekAction/executeAction/runToCompletion/watch); multi-**lane** sessions (`createLane(name, at)`) share one session tree; operations return typed `Result` unions with tagged rejections (LaneBusy/MissingIdentities/…), never throws [src: agent/src/harness/agent-harness.ts:27-132,271-303].
- **Event-sourced durable core:** a single-writer **record log** (operation_started/abort_requested/operation_finished/queue_enqueued/step_attempt/tool_started/write_deferred…) plus entries; `reducer.ts` rebuilds lane state and defines a **12-reason `RecordLogCorruption` taxonomy** (multiple_open_operations, tool_call_mismatch, duplicate_tool_invocation…); restore must reject, not repair [src: harness/session/types.ts:80-120, reducer.ts:15-44].
- **`ExecutionEnv` = `FileSystem` + `Shell`** capability interfaces with stable backend-independent error codes and a never-throw contract; `env/nodejs.ts` is the Node implementation. This is a same-world provider seam in all but name — routing it moves read/write/edit/bash/grep/find/ls together [src: harness/types.ts:128-315, harness/env/nodejs.ts].
- **Deterministic drive & replay:** `drive:"automatic"|"manual"`, `ActionInfo` enumerates machine steps (append_entry, stream_assistant, execute_tool, fetch_deferred, hook, sleep…); `HarnessTool.replay?: "never"|"safe"` marks replayability; `RunOutcome` includes `"suspended"` carrying a provider `DeferredHandle` [src: agent-harness.ts:89-103,237; harness/session/conformance.ts].
- The coding agent does **not** use this yet (old path is production); conformance tests (946 LOC) + `pi-server/testing` wire conformance exist. **Inference:** this subsystem is where pi is converging on DSH-style seams/event-sourcing — flagged inference, design intent not documented in prose [src: grep; conformance.ts].

### 5. Coding agent: surface & defaults (D3/D4)

- **Four run modes:** interactive TUI (default), `-p` print, `--mode json` (all events as JSON lines), `--mode rpc` (JSONL over stdio); plus the SDK (`createAgentSession()`, `AgentSessionRuntime` for session replacement: new/resume/fork/import rebind cwd-bound services) [src: coding-agent README §Programmatic Usage; docs/sdk.md:114-153].
- **Default toolset: 4 tools** (`read`, `write`, `edit`, `bash`); built-ins available: + `grep`, `find`, `ls`, `powershell` (Windows). Windows requires bash (Git Bash checked from settings/path). Read-only via `--tools read,grep,find,ls`. **No** todos/plan-mode/subagent/MCP/background-bash tools — each is an explicit philosophy non-feature (see §10) [src: README §Philosophy; core/tools/ listing; docs/windows.md].
- **`!`/`!!` user bash** with `user_bash` extension interception (custom operations = remote exec seam); bash tool passes session metadata env (`PI_SESSION_ID`, `PI_MODEL`…) to child commands [src: README; docs/extensions.md §user_bash].
- **llama.cpp integration** is a built-in extension (`/login llama.cpp`, `/llama` download/load/unload, `/model` selection; ~1.3k LOC) — local-model path treated as a provider, not a separate mode [src: README; src/extensions/llama/].
- **Context files:** AGENTS.md/CLAUDE.md concatenated from global + ancestors + cwd, `AGENTS.override.md` per-dir substitution; SYSTEM.md/APPEND_SYSTEM.md replace/extend the default system prompt [src: README §Context Files].

### 6. State/session model (D15/D6)

- **Sessions = JSONL trees:** every entry has `id`/`parentId`; branching happens **in place** (`/tree` navigates and continues from any point; `/fork` and `/clone` create new files; `--fork` from CLI). Entry types: message, model_change, thinking_level_change, compaction (with `retainedTail` self-contained checkpoint), branch_summary, custom (extension state, *not* model-visible), custom_message (extension-injected, model-visible), label, session_info; format v3 with auto-migration from v1/v2 [src: docs/session-format.md].
- **Compaction:** auto on `contextTokens > contextWindow − reserveTokens` (16,384) + proactive + overflow recovery (`shouldStopAfterTurn` aborts, compacts, retries); `keepRecentTokens` 20k; cut never at tool results; split-turn double-summary; structured summary format (Goal/Constraints/Progress/Key Decisions/Next Steps + cumulative `<read-files>`/`<modified-files>` tracking across compactions); fresh routing session IDs + prompt-cache writes disabled for one-off summary calls; fully extension-customizable (`session_before_compact` can cancel or supply the summary) [src: docs/compaction.md].
- **Branch summarization:** `/tree` jumps generate an LLM summary of the abandoned path and inject it as `branchSummary` — tree navigation without context loss. **No DSH equivalent.** [src: docs/compaction.md §Branch Summarization]
- **Session search:** `agent/src/search/` (scanning search over storage, entry-type filters, abortable) backs `/tree` search; SQLite backend adds branch/facts/log queries [src: agent/src/search/index.ts; session-backends/sqlite-node test listing].
- **Backends:** JSONL files (`~/.pi/agent/sessions/--<path>--/<ts>_<uuid>.jsonl`) default; `pi-session-backend-sqlite-node` separate package so the core pulls no native builtins (accepts a runtime-specific SQLite factory) [src: agent/README.md §SQLite session backends].

### 7. Extensions — the load-bearing seam (D2/D4)

- **One seam, maximal depth:** extensions are TypeScript modules (loaded via **jiti**, no build step) exporting `default (pi: ExtensionAPI) => …`; async factories awaited before `session_start`. Discovery: `~/.pi/agent/extensions/` (global), `.pi/extensions/` (project, trust-gated), settings paths, `-e` CLI; hot-reload via `/reload` [src: docs/extensions.md §Quick Start/§Locations].
- **ExtensionAPI (~30 methods):** registerTool (runtime, dynamic, with `promptSnippet`/`promptGuidelines` system-prompt integration + `prepareArguments` shim), registerCommand (conflicts get `:1`/`:2` suffixes), registerShortcut, registerFlag (custom CLI flags!), registerProvider/unregisterProvider (full pi-ai `Provider` objects, OAuth, `refreshModels`, or legacy config incl. `$ENV`/`!command` key references), sendMessage/sendUserMessage (deliverAs steer/followUp/nextTurn + `triggerTurn`), appendEntry (durable non-model state), setLabel, registerMessageRenderer/registerEntryRenderer/registerMarkdownTransformer, get/setActiveTools, setModel/setThinkingLevel, pi.exec, pi.events (cross-extension bus) [src: docs/extensions.md §ExtensionAPI Methods].
- **~40 event hooks across the whole pipeline:** project_trust, session_start/shutdown/before_switch/before_fork/before_compact(+compact/compact_failed)/before_tree/tree, resources_discover, input (intercept/transform/handle *before* skill/template expansion), before_agent_start (inject message + chained systemPrompt rewrite with structured `systemPromptOptions`), context (per-LLM-call message rewrite on a deep copy), **before_provider_headers / before_provider_request (payload replacement) / after_provider_response (status+headers pre-consume)**, tool_call (block + mutate args in place; no re-validation after mutation), tool_result (middleware chain, can attach nested-model `usage`), user_bash, ui_prompt_start/end, model_select, thinking_level_select, agent_settled [src: docs/extensions.md §Events; verified lifecycle diagram lines 277-349].
- **ctx surface:** ui (select/confirm/input/notify + **custom TUI components**, editor takeover, widgets, status lines, footers, autocomplete providers), sessionManager, modelRegistry, signal (Esc-cancellable), isIdle/abort, getContextUsage, compact, getSystemPrompt; command ctx adds newSession/fork/navigateTree/switchSession/reload with a documented session-replacement lifecycle [src: docs/extensions.md §ExtensionContext, §ExtensionCommandContext].
- **Pi Packages:** bundle extensions+skills+prompts+themes; `pi install npm:|git:|https:|path` (+`@ref` pinning, `-l` project-local), `pi config` enable/disable, `pi list/update`; `pi` manifest key or conventional dirs; peer-deps convention (list pi packages as `"*"` peerDependencies, don't bundle) [src: docs/packages.md; README §Pi Packages].
- **Skills** implement the agentskills.io spec (lenient: allows name≠dirname for shared dirs), progressive disclosure (descriptions in XML system-prompt block, full body on `/skill:name`), sources across `~/.pi/agent/skills`, `~/.agents/skills`, `.pi/skills`, `.agents/skills` (cwd→git-root walk), `disable-model-invocation` frontmatter; prompt templates as `/name` markdown macros [src: docs/skills.md].

### 8. UI layers (D16)

- **pi-tui** is a standalone library: differential rendering, CSI-2026 synchronized output, main/alternate screen renderers, component model, built-ins (Editor, Markdown, SelectList, Image with Kitty/iTerm2 protocols), themes as hot-reloadable JSON [src: tui/README.md; README §Themes].
- Interactive mode = one app over AgentSession: header (loaded resources), transcript, editor (border = thinking level), footer (cwd, tokens/cache/cost/context, model); `/settings` in-TUI; extension UI slots are rich (replace editor, widgets above/below, status line, overlays) — the TUI extension surface is Pi's equivalent of DSH's browser slot system [src: README §Interactive Mode; docs/extensions.md §Custom UI].
- **No web UI ships** in this repo at this SHA (web-ui package removed since the 0.5x-era docs; pi-chat/Slack moved to earendil-works/pi-chat) — terminal-first by design [src: repo packages listing vs search-index snapshots].

### 9. Client/server boundaries (D10/D16)

- **RPC mode** (production): LF-delimited JSONL over stdio, id-correlated commands (prompt/steer/follow_up/abort/clear_queue/set_steering_mode/set_follow_up_mode/get_commands…) + streamed events; strict `\n` framing documented against Node readline (U+2028/2029); subprocess TS client included. This is the IDE-embedding surface [src: docs/rpc.md].
- **pi-protocol/client/server** (experimental): runtime-neutral **CBOR length-prefixed binary protocol** (strict RFC 8949 subset, unknown-property rejection, 16 MiB frames, versioned hello); **snapshot-authoritative semantics** — server/session snapshots are truth, progress events are transient hints; `PiClient` with exclusive/shared **SessionLeases**, correlated requests, no auto-reconnect; `PiServer` composes listeners (Unix socket preset; WebSocket-shaped) with transport-time auth; pi-ai↔protocol bridge with compile-time field manifests so new pi-ai fields fail the build until reviewed [src: protocol/README.md; client/README.md; server/README.md].
- **SDK in-process path:** `createAgentSession()` (ResourceLoader abstraction over extensions/skills/themes/prompts/context files) and `createAgentSessionRuntime()` for multi-session replacement; coding-agent `src/client/RemoteSession`+`transcript.ts` already model snapshot/progress application client-side [src: docs/sdk.md; src/client/index.ts].

### 10. Security posture & telemetry (D13/D14/D19)

- **Deliberately no built-in sandbox/permission system:** "a partial in-process sandbox would be easy to misunderstand as a security boundary"; runs with user permissions; **project trust** is an *input-loading guard only* (`.pi` resources + project packages + `.agents/skills` gated; global/CLI extensions load pre-trust and can own the `project_trust` decision; saved decisions in `trust.json`, `defaultProjectTrust: ask|always|never`, `--approve/--no-approve`); isolation delegated to OS boundaries — documented patterns: **Gondolin** micro-VM extension (host pi + VM-routed built-in tools + `!`), plain Docker, **NVIDIA OpenShell** (policy sandbox, local or K8s gateway, inference routing keeps keys outside) [src: docs/security.md; docs/containerization.md; README §Permissions & Containerization].
- **Supply-chain hardening** is the security center of gravity: exact-pinned deps, `save-exact` + `min-release-age=2`, lockfile ground truth with pre-commit gate, generated shrinkwrap with lifecycle-script allowlist, `--ignore-scripts` installs, OIDC trusted publishing, release smoke tests, audited CI [src: README §Supply-chain hardening; AGENTS.md].
- **Telemetry:** `pi-telemetry` = vendor-neutral callback-based span contracts (no exporter, explicit contexts, in-memory reference + conformance); product telemetry is modest and disclosed (pi.dev version check + anonymous install/update ping + provider attribution headers; `PI_OFFLINE`/`PI_TELEMETRY=0` kill switches) [src: telemetry/README.md; README §Telemetry and update checks].
- **Evals as a package:** `pi-evals` adapts a real AgentSession to vitest-evals in isolated temp dirs, attaching native session JSONL artifacts; plus **public session sharing to HuggingFace datasets** (badlogic/pi-share-hf; author publishes his own sessions) — real-workflow benchmark data as a deliberate ecosystem bet [src: evals/README.md; README §Share your OSS sessions].

## The small-core reveal (ticket's special angle)

1. **One deep seam can stand in for a composition grammar.** Pi's bet: a jiti TS module with events at every pipeline stage (input → context → provider headers/payload → tool_call → tool_result → session lifecycle) plus runtime registration (tools, commands, flags, providers, UI) covers what DSH spreads across ~50 seams + patch layering + 4 dispatch modes. The cost pi pays: no layering/reversibility (no HMR-safe registration effects — `/reload` re-runs factories), no config-only composition (everything is code), duplicate-command suffixes instead of scoped shadowing. The cost DSH pays for its grammar: an extension author must learn Cordis, patches, and seam roles; pi's author writes one function. Neither dominates — but pi proves "everything is an extension API" is viable where "everything is a plugin row" was DSH's axiom.
2. **Product features are downstream of the seam, not the core.** Subagents, plan mode, permission gates, todos, MCP, background bash — six things DSH ships as core/seams — all exist in pi as *documented extension ideas or examples*. DSH's baseline treats these as capability dimensions; pi reframes them as *packaging choices*. For the capability map this means: where a dimension exists in pi as "extension-shaped," the honest entry is the extension surface, and absence-of-core is not absence-of-capability — the inverse of nanobot, where absence was genuine absence.
3. **The minimal core is not stable — it is re-growing DSH's organs on demand.** The `harness/` rewrite adds exactly: same-world execution seams (`ExecutionEnv`), an append-only record log + reducer + corruption taxonomy, replay-marked tools, deterministic action stepping, conformance tests, snapshot protocols with leases. Every one of those is a DSH flagship mechanism. The strongest signal in this profile: a minimalist author, needing remote sessions and crash recovery, converges on DSH's decomposition — evidence DSH's plugin/runtime split describes a real gravity well rather than overengineering.
4. **DSH already sits on pi's substrate.** `dsh-llm-pi-ai` wraps `@earendil-works/pi-ai` for provider portability, tracking its catalog releases. The "provider abstraction" dimension of the map is not a comparison — it is a shared component. Changes in pi's provider/auth model (credential store semantics, OAuth, compat flags) propagate into DSH through that pin; the map should record the dependency edge, not just parity.
5. **Session-model heresy worth charting:** pi branches in place (tree + branch summaries) where DSH forks copies (balanced prefix). Pi's model preserves all history in one file and makes abandoned-context recovery a first-class LLM operation; DSH's keeps the log as single source of truth and forking as an explicit act. Both defensible; the branch-summary primitive (summarize the path you leave) has no DSH analogue and is cheap to state in DSH terms (a compaction variant on fork).
6. **Security decomposition:** pi splits the problem at the OS boundary (trust gate for *inputs*, containers for *execution*, extensions for *policy popups*) where DSH integrates it in-process (sandbox modes, approval waterfall, freshness guards). Pi's docs argue the in-process middle is a false comfort. DSH's one-shot escalation + OS confinement runners sit closer to the middle; the map should treat this as a genuine design fork, not a maturity gap.
