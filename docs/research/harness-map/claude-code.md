# Claude Code: architecture & distinctive capabilities (vs DSH baseline)

**Baseline for: Agent Harness Capability Map (profile #16 of 18)**

- **Researched:** 2026-08-30 (in-session). **Subject:** Anthropic Claude Code, **closed source** — every mechanism claim below is doc-depth; internals (loop, tool pipeline, compaction) are not inspectable and are not guessed.
- **Evidence tiers:** **[docs]** official docs fetched 2026-08-30 as raw markdown from `code.claude.com/docs/en/<page>.md` (166-page index pinned via `code.claude.com/docs/llms.txt`); **[changelog]** `anthropics/claude-code` CHANGELOG.md at main = `92bb6850f1bb51f4d18b03b23d643642f9d687b6` (2026-08-28), top entry 2.1.250; **[pkg]** npm `@anthropic-ai/claude-code` v2.1.250 (published 2026-08-27): `bin/claude.exe`, **zero runtime deps**, 8 platform binaries as optionalDependencies (linux/darwin/win × x64/arm64 + musl) → native compiled binary, not a JS bundle (native binaries replaced bundled JS per changelog w16 2026); **[blog]** claude.com/anthropic.com first-party posts (some engineering-blog slugs 404'd at fetch time; docs supersede).
- **DSH comparison:** `dsh-baseline.md` pinned `b150a55`; §7 taxonomy D1–D20, capability names verbatim. **Key sources:** how-claude-code-works, features-overview, permissions, permission-modes, sandboxing, sandbox-environments, tools-reference, hooks(+guide), sub-agents, skills, memory, plugins(-reference), plugin-marketplaces, mcp, sessions, checkpointing, workflows, agent-teams, agent-view, goal, scheduled-tasks, channels(-reference), cross-session-messaging, worktrees, model-config, prompt-caching, headless, statusline, computer-use, artifacts, routines + Agent SDK pages (overview/hosting/…).

**Verdict.** Claude Code is the field's most productized terminal coding agent: a closed-source native binary whose *architecture is its configuration contract* — a fixed core loop plus a deep, layered filesystem interface (`.claude/` + `~/.claude/`: settings, rules, skills, agents, hooks, commands, workflows, auto memory, plugins, marketplaces) that replaces anything like DSH's runtime-composable plugin tree. Three choices matter most against DSH. (1) **Permissions as the primary product plane**: six modes (Manual/acceptEdits/plan/**auto**/dontAsk/bypassPermissions) plus a rule engine (`deny>ask>allow`, bash prefix wildcards, parameter matching, bare-name deny *removes the tool from the model's context*) plus a separate OS-enforced Bash sandbox (Seatbelt/bubblewrap) — where DSH has one guarded pipeline with one-shot-only grants and no persisted allow-rules. **Auto mode** is distinctive in kind: a second LLM ("classifier") reviews each action instead of the human; it is now the built-in default on Pro/Max/Team interactive sessions [docs]. (2) **Cross-session and cross-surface continuity**: plaintext JSONL transcripts per project dir, resume/fork/`--from-pr`, per-subagent transcripts, cross-session `SendMessage`/`ListAgents` between sessions on one machine, agent view's background supervisor, `--cloud`/`--teleport` to hosted web sessions, Remote Control, mobile — DSH keeps session state per host process with no inter-session bus. (3) **Memory as a shipped capability**: auto memory (`MEMORY.md` index + typed topic files per project, machine-local, loaded every session) and per-subagent persistent memory scopes (`memory: user|project|local`) — the exact dimension (D7) DSH declares absent by design. Claude Code is also the ecosystem's **de-facto standard-setter**: SKILL.md + agentskills.io spec, hooks event vocabulary, `.claude-plugin` plugin/marketplace layout, and MCP-in-terminal (shipped pre-1.0, changelog 0.2.31) are formats other harnesses in this map (OpenHands, OIX) have adopted. Its counter-limits vs DSH: no runtime composability (nothing swappable at config depth), single vendor/models-first (multi-provider exists only as enterprise cloud/gateway routing), and no event-sourced invariant — transcripts are internal-format message logs that "change between versions" [docs: sessions].

## 1. Runtime & loop [docs: how-claude-code-works]

- **Agentic loop** = gather context → take action → verify, blending per task; user can interrupt (Esc) or queue steering messages mid-turn. Loop internals closed; no admission-control or swappable-loop equivalent is documented (contrast DSH `agent/pre-step` waterfall, `ctx.agentLoop` bundle row).
- **Sessions**: plaintext JSONL at `~/.claude/projects/<project>/<session-id>.jsonl` (project = cwd path flattened); each line a message/tool-use/metadata object; format explicitly internal and version-unstable; subagent transcripts separate (`…/{sessionId}/subagents/agent-<id>.jsonl`); 30-day `cleanupPeriodDays` sweep; `--no-session-persistence`, `/export`. Resume (`--continue`/`--resume`/picker) appends under the same session id; fork (`--fork-session`, `/branch`) copies history to a new id [docs: sessions].
- **Parallelism planes** [docs: agents]: subagents (own context) · **agent view** (`claude agents`: full sessions in background worktrees under a **supervisor process**, peek/reply/attach, dispatch) · **agent teams** (lead + teammates = *separate Claude Code processes*, tmux panes or in-process, JSON-file mailboxes at `~/.claude/teams/<team>/inboxes/*.json`, shared task list `~/.claude/tasks/<team>/`, auto-managed dependencies, shutdown/plan-approval protocols) · **dynamic workflows** (below).
- **Agent SDK** = subprocess model: the SDK "spawns and supervises a `claude` CLI subprocess that owns a shell, a working directory, and session files" [docs: agent-sdk/hosting] — i.e., the CLI *is* the runtime library; TS/Python SDKs wrap it. Headless `claude -p` with `--output-format text|json|stream-json`, structured `--output-schema`, and **`--bare`** (skips all auto-discovery — hooks/skills/agents/plugins/MCP/CLAUDE.md/auto memory — for hermetic CI runs) [docs: headless].

## 2. Tools [docs: tools-reference]

- Built-ins: `Bash` (+`PowerShell` on Windows), `Read`/`Edit`/`Write`/`NotebookEdit`, `Glob`/`Grep`, `WebFetch`/`WebSearch`, `Agent`, `AskUserQuestion`, `TodoWrite` + `TaskCreate/Get/Update/List`, `Skill`, `Monitor`, `LSP` (inactive until a code-intelligence plugin adds a language server), `SendMessage`/`ListAgents` (cross-session), `ScheduleWakeup`, `Workflow`, `EndConversation` (undeniable), `SendFeedback`; permission-mode-aware plan tooling.
- **WebFetch is a lossy small-model extraction pipeline**: fetch → HTML→Markdown → prompt evaluated by "a small, fast model"; Claude sees the answer, not the page; 15-min response cache; redirect-then-refetch [docs]. Distinctive vs any DSH fetch design (DSH ships `web_fetch` disabled pending SSRF policy).
- **Model-conditional tool omission**: on Opus 4.8/Sonnet 5/Fable 5+ the todo/task tools are *removed by default* (models "keep track without a written checklist"; opt-in via env/flag) [docs] — the deliberate inverse of DSH's KV-cache "tool catalog constant" discipline.
- **Monitor tool**: model-authored background watch scripts + native **WebSocket source**; each output line delivered into the conversation as it arrives; permission-rule parity with Bash [docs].
- **MCP tool search** (default on): only tool *names* + server instructions load; full schemas resolved on demand via `ToolSearch`; 10-min-scale `WaitForMcpServers` fallback; long MCP calls auto-background [docs: mcp].

## 3. Permissions & approvals [docs: permissions, permission-modes, auto-mode-config]

- **Rule engine**: `allow`/`ask`/`deny` lists of `Tool` or `Tool(specifier)`; evaluation deny→ask→allow, first match wins, specificity irrelevant; `Bash(npm run *)` prefix wildcards (* placed before the subcommand triggers a startup warning); `Tool(param:value)` deny/ask matching on scalar inputs (e.g. `Agent(isolation:worktree)`), primary content fields excluded as bypassable; bare-tool deny **removes the tool from context** (model never sees it) ≈ DSH `tools.restrict` "one visibility". Persisted approvals land in `.claude/settings.local.json` at repo root (worktree-resolved) — permanent per repo+command, vs DSH's one-shot-only `allowed-once`.
- **Modes**: `default`/Manual, `acceptEdits`, `plan` (read-only + plan approval gate), **`auto`** (classifier auto-approves with background safety checks; actions no mode auto-approves: ask rules, `AskUserQuestion`, org-asked connectors, critical-path `rm`, cross-session safeguards), `dontAsk` (deny-unless-preapproved, for CI), `bypassPermissions` (containers/VMs only; `--dangerously-skip-permissions`). Shift+Tab cycles; starting mode is plan-dependent (auto default on Pro/Max/Team interactive; Manual for `-p`/SDK/Enterprise/Bedrock). Deny rules hold even in bypass; org can `disableBypassPermissionsMode`/`disableAutoMode`.
- **Approval UX**: "Yes, and don't ask again" variants; **Ctrl+E** on-demand LLM explanation of a command (low/med/high risk); Tab-attached comments on Yes/No (No+comment → denial reason fed to the model ≈ OpenCode's reject-with-feedback).
- **Sandbox** (Bash tool only, macOS/Linux/WSL2): OS enforcement Seatbelt / **bubblewrap**; filesystem isolation + network isolation via mandatory proxy; protected paths; credential masking; `/sandbox` panel; auto-allow mode (sandboxed commands skip prompts; overrides may fall back unsandboxed per setting); standalone `@anthropic-ai/sandbox-runtime` wraps the whole process; sandbox-environments page ranks Bash sandbox / runtime / dev containers / Docker / VMs [docs: sandboxing, sandbox-environments]. No native-Windows sandbox (DSH ships an ACL WRITE_RESTRICTED runner — parity difference).

## 4. Hooks [docs: hooks, hooks-guide]

- Five **handler types**: `command` (shell, JSON on stdin, exit-code semantics: 2 = block w/ stderr fed to model), **`prompt`** (LLM evaluation returning `{ok, reason, impossible}` — a hook that *is* a model call), `http`, MCP tool call, subagent. Config: settings JSON (user/project/local/managed) or plugin `hooks/hooks.json`; event → matcher → handlers nesting.
- ~30 events: `SessionStart/End`, `UserPromptSubmit`, `PreToolUse`/`PostToolUse`(+Failure/Batch), `PermissionRequest`/`PermissionDenied`, `SubagentStart/Stop`, `Stop`, `PreCompact`/`PostCompact`, `Notification`, `TeammateIdle`, `TaskCreated`/`TaskCompleted`, `WorktreeCreate/Remove`, `FileChanged`, `ConfigChange`, `Elicitation*`… — far broader event surface than DSH's ~13 core session events, exposed *to users as config*, not just plugin authors.
- Docs frame the deterministic-vs-prompt split explicitly: "an instruction in CLAUDE.md is a request, not a guarantee… a PreToolUse hook that blocks is enforcement" [docs: features-overview].

## 5. Skills, subagents, memory [docs: skills, sub-agents, memory]

- **Skills**: `SKILL.md` dirs at enterprise/personal/project/plugin scopes (+nested per-directory with dir-qualified names; claude.ai-synced skills; `metadata`/`license`/`compatibility` fields align to the external **agentskills.io** spec, a subset of what the CLI accepts). Progressive disclosure: name+description (+`when_to_use`, 1,536-char cap) every request, full body on invoke; `disable-model-invocation`, `user-invocable:false`, `allowed-tools` (per-turn pre-approval), `disallowed-tools`, `context: fork` (skill runs as a forked subagent), `model`/`effort` overrides, `paths` glob gating, `hooks`, inline `` !`cmd` `` dynamic-context injection (bash or powershell). Skills-as-plugins: a `plugin.json` in a skill folder loads it as `<name>@skills-dir`.
- **Subagents**: markdown+YAML in `.claude/agents/` (scopes: managed > CLI `--agents` JSON > project > user > plugin). Frontmatter: `tools`/`disallowedTools`, `model` (aliases incl. `inherit`), `permissionMode`, `maxTurns` (partial output + resume), `skills` (full preload), `mcpServers` (incl. inline server defs), `hooks` (scoped), **`memory: user|project|local`** (per-agent persistent memory dir + `MEMORY.md` head injected), **`isolation: worktree`** (temp git worktree, auto-cleaned), `effort`, `background`, `color`, `initialPrompt`. Built-ins: **Explore** (read-only, model inherited capped at Opus, thoroughness levels) and **Plan** — both deliberately *skip CLAUDE.md and git status* for cheap fast context. Auto-delegation by description matching; explicit `/agents`-style invocation; background-by-default with prompts surfaced to the parent terminal; **fork mode** (fork = subagent inheriting the full parent conversation, `/subtask`); SendMessage resume with anti-retargeting name checks; sibling roster reminder; independent auto-compaction.
- **Auto memory** (D7!): on by default; four typed notes (`user`/`feedback`/`project`/`reference`) written by Claude itself; skips anything derivable from code or already in CLAUDE.md; `~/.claude/projects/<project>/memory/` shared across worktrees of one repo, machine-local; `MEMORY.md` index (first 200 lines/25 KB loaded at session start) + topic files; excluded from retention sweeps; auditable via `/memory`.

## 6. Context & session handling [docs: how-claude-code-works, prompt-caching, context-window]

- Auto-compaction with configurable window (`/compact` w/ focus; CLAUDE.md "Compact Instructions" section; thrashing → stops + errors); `/context` token inspector; older tool outputs cleared first.
- **Prompt caching as a documented architectural discipline**: 3-layer request ordering (system+tool defs → project context CLAUDE.md/memory/rules → conversation); invalidation taxonomy (model switch, effort, fast mode, MCP connect/disconnect, plugin enable, whole-tool deny, compact, upgrade) vs cache-preserving actions (file edits, permission-mode change, skill invocation, plan mode — plan/skill content appended as conversation messages, not system edits); TTL buckets, per-subagent cache TTL setting, **workflow fan-out prefix stagger** (hold siblings ≤5 s so the first writer warms the shared prefix) [docs: prompt-caching, workflows] — a deep KV-cache-stability kinship with DSH, one layer deeper (mechanics + tuning knobs).
- Checkpoints: per-edit file snapshots (separate from git; survive resume; symlink/hardlink gaps; remote actions not covered) + conversation rewind (Esc Esc / `/rewind` incl. pre-`/clear`) [docs: checkpointing].
- `/goal`: a session-scoped **prompt-based Stop hook** — small fast model judges met/not-yet/impossible each turn; unrecoverable errors (auth, credits, compaction-uncleared overflow, model unavailable) clear the goal; background work defers evaluation with 30-min→2h backoff check-ins [docs: goal] (vs DSH's structured `ctx.goals` CAS-revision protocol — same capability, judgment delegated to an LLM hook).

## 7. Plugins, marketplaces, MCP [docs: plugins-reference, plugin-marketplaces, mcp]

- **Plugin** = self-contained dir, optional `.claude-plugin/plugin.json` manifest (auto-discovery otherwise), components: `skills/`, `agents/`, `hooks/hooks.json`, MCP servers, **LSP servers** (`.lsp.json` — how code intelligence ships), **monitors**, **themes**, output styles, commands, workflows; plugin skills namespaced `plugin:skill`; Node `dependencies` w/ **version constraints**; install scopes (user/project/local), zip/URL/git sources; `plugin validate`/`init`/`prune` CLI. **Marketplaces**: hosted collections (git repos, GitHub Enterprise support) with `plugin-hints` (CLIs emit a marker so Claude Code offers their plugin) and relevance blocks (org-tuned suggestions). First-party examples: security-guidance, Claude Security, code-intelligence plugins.
- **MCP**: 4 transports (stdio, streamable HTTP, SSE, WebSocket); scopes local(`~/.claude.json`)/project(`.mcp.json` w/ env expansion)/user; OAuth (`claude mcp login`, fixed callback port, scope restriction, dynamic headers); auto-reconnect; dynamic tool updates; `claude.ai` **connectors** (org-controlled remote servers); `claude mcp serve` = Claude Code *as* a stdio MCP server; **Channels** (research preview): MCP servers that *push* events into a running session (Telegram/Discord/iMessage bridges; capability-declared, permission-relayed reply tools) — an inbound-transport role DSH's inbox seam plays only internally.

## 8. Repo workflows & surfaces [docs: common-workflows, worktrees, github-actions, chrome, computer-use, artifacts, routines]

- Git-native: commits/PRs; **worktrees as first-class isolation** (`--worktree`, subagent `isolation`, background-session worktrees under `.claude/worktrees/`, `.worktreeinclude`, worktree hooks); GitHub Actions (`@claude` mentions, issue→PR, `/code-review` + **ultrareview** cloud multi-agent review) and GitLab CI/CD; cloud PR auto-fix; large-codebase guide (nested CLAUDE.md, sparse worktrees, per-package skills).
- Surfaces: terminal TUI (plan approval, queued messages, vim mode, fullscreen rendering, voice dictation, screen-reader mode, Ctrl+R cross-project history), **statusline** (user script fed JSON: context-window, cost, rate-limit fields — the TUI's one composable widget), VS Code/JetBrains extensions, Desktop app (parallel panes, iOS-simulator pane, Dispatch, scheduled tasks, computer use), web + mobile (`--cloud`/`--teleport`, Remote Control = browser driving local execution), Slack (@Claude / Claude Tag), Chrome extension, `claude-cli://` deep links, published **Artifacts** (interactive claude.ai pages, MCP-connector-live). Computer use in CLI = macOS research preview.
- Models [docs: model-config]: aliases sonnet/opus/haiku/fable; **`opusplan`** (plan on Opus, execute on Sonnet); effort `low…xhigh` + **ultracode** (auto-workflow escalation); fast mode; **advisor tool** (pair a stronger advisor model consulted at key moments); automatic model fallback chains; per-skill/subagent model+effort overrides; org allowlists.

## 10. De-facto standard-setter record (for the map's convergence notes)

1. **SKILL.md + agentskills.io** — DSH skill discovery already reads SKILL.md; OpenHands/others adopted the format. 2. **Hooks events + exit-code-2 blocking** — sibling profiles (OpenHands) ported the vocabulary. 3. **`.claude-plugin/plugin.json` + marketplaces** — becoming the terminal-agent plugin packaging norm. 4. **MCP-in-terminal** — shipped before 1.0 (changelog 0.2.31), normalized MCP for coding agents. 5. **Workflow script API (`agent()`/`pipeline()`)** — DSH's `workflow` tool is API-identical; either common ancestry or convergent design. 6. Permission-rule syntax `Bash(npm run *)` widely imitated across TUI agents.
7. **Direct interop already exists DSH-side**: the DSH baseline (D3) ships an opt-in `subagent-claude-code` bundle — Claude Code as an *external-harness subagent provider* behind DSH's one subagent seam; and OIX-style portability efforts (per sibling profiles) treat CC's formats as the portability target. The map's edges to CC are therefore both "adopts its formats" and "wraps its binary".

## 11. Uncertainties / open questions

1. **Mechanism depth**: everything above is doc-depth; loop internals, tool-pipeline structure (frozen args? post-rewrite?), compaction algorithm, classifier model/inputs are closed. Do not infer DSH-shaped internals.
2. **Version churn**: docs describe 2.1.x (2026-08) with weekly whats-new; features flip defaults fast (auto mode default v2.1.228/233; fork mode on by default w33). Re-pin changelog before quoting.
3. Whether CC's MCP client surfaces **resources/prompts** (docs are tools-centric; only tool search, instructions, channels documented) — unresolved.
4. Agentskills.io is Anthropic-backed but externally hosted; CC accepts a superset of spec fields — which fields other harnesses implement varies (check per profile).
5. Agent-teams display modes (tmux vs in-process) and cross-session messaging transport details are described only at behavior depth.
6. `Task tools` model-conditional availability is model-plan-specific; treat as current-family behavior, not stable contract.
7. Some first-party engineering-blog URLs moved (404 at fetch); blog-tier claims here are covered by docs, so none rest on dead links.
