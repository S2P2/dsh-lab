# OpenCode: architecture & distinctive capabilities (vs DSH baseline)

**Baseline for: Agent Harness Capability Map (profile #15 of 18)**

- **Researched:** 2026-08-30 (in-session)
- **Repo:** `github.com/sst/opencode` → now `github.com/anomalyco/opencode` (org rename; `sst/opencode` serves identical commits as redirect — `git ls-remote` on both returned the same HEAD; README badges/npm install script point at `anomalyco`). **Pinned SHA `15537a41d2a0514f7040e1c4128b7846cdc19ce0`** (2026-08-27, "fix(opencode): compare config snapshots as JSON (#45784)", default branch `dev`), shallow sparse clone (`--depth 1 --filter=blob:none --sparse`) in-session; all in-repo refs at that SHA. npm package `opencode-ai`; product https://opencode.ai.
- **Docs:** in-repo `packages/web/src/content/docs/` + live docs pages (opencode.ai/docs/{server,web,share,config}, fetched 2026-08-30 via web search snapshots).
- **DSH comparison:** `dsh-baseline.md` pinned `b150a55`; §7 taxonomy D1–D20, capability names verbatim.
- **Source key:** unqualified paths are `packages/opencode/src/…` at the pinned SHA unless prefixed `packages/<pkg>/` or *docs:*.

**Verdict.** OpenCode is the field's most **server-first** coding agent: one Bun/TS host process (now Effect-TS throughout — `Context.Service`/`Layer`/`LayerNode` static dependency graph replacing the old class DI) exposes a typed HTTP+WebSocket API with a published OpenAPI 3.1 spec from which its SDK clients are generated, and *every* surface — TUI (Solid/OpenTUI), web app, Electron desktop, VS Code extension, ACP (Zed), third-party mobile apps, even plugins and the ACP service itself — is a client of that API. Two choices matter most against DSH. First, **policy-based safety instead of confinement**: OpenCode has no OS sandbox at all (its "sandboxes" are git worktrees); safety is a declarative pattern-permission engine — allow/ask/deny rules with glob patterns over tool names, file paths, bash command prefixes (tree-sitter parsed), and even subagent names, merged defaults→agent→user with last-match-wins, plus once/always/reject-with-feedback replies and doom-loop detection — where DSH enforces file-effect sandbox modes with OS runners and one-shot-only grants. Second, **product-shaped state instead of event sourcing**: sessions live in SQLite as message/part rows (with per-step file snapshots and diffs as parts, revert/unrevert on top) rather than an append-only event log with a model-visible-means-logged invariant; both get fork/resume/replay-ish outcomes by different routes. Distinctive beyond DSH's surface: agents-as-config (markdown+frontmatter, per-agent permission rulesets, LLM-generatable), model-conditional tool selection (apply_patch on GPT vs edit/write), compaction/title/summary as hidden deny-all agents, models.dev as shared model catalog with per-model cost/limits, npm-loaded custom provider SDKs, an opt-in first-party native LLM runtime, session share URLs, remote workspaces with live session "warp", mDNS LAN discovery, first-party Slack bot + GitHub agent, and managed MDM config. DSH's counter-absences: OS confinement, everything-is-a-plugin composition, in-process event interception, goals/workflows/Ralph, KV-cache stability discipline (OpenCode actively diverges).

## 1. Positioning & repo layout

- **Positioning** (README.md): "The open source AI coding agent." Two built-in primary agents (`build`, `plan`), `general`/`explore` subagents; desktop app (beta); npm `opencode-ai` + brew/scoop/choco/pacman/nix/mise + native compiled launcher (`packages/cli/bin/lildax.cjs` resolves `@opencode-ai/cli-<plat>-<arch>` binaries with AVX2 detection) + install script. Repo self-hosts agent conventions (`AGENTS.md`, `CONTEXT.md` at root — dogfooding signal).
- **Monorepo** (`packages/`): `opencode` (core ~30 subsystem dirs), `tui` (SolidJS over `@opentui/solid` — rewritten from Go), `app` (web client), `desktop` (Electron), `web` (Astro docs/lander), `console` (team console), `cli` (`@opencode-ai/cli`, service subcommands), `server`, `client` (generated promise/Effect clients "derived directly from OpenCode's authoritative Effect `HttpApi`"), `sdk`, `plugin` (plugin authoring pkg, v1 hooks + `v2/` Effect API), `protocol`, `llm` ("schema-first LLM core"), `codemode`, `slack`, `enterprise` (SolidStart), `session-ui`, `identity`, `stats`, `httpapi-codegen`, `effect-drizzle-sqlite`/`effect-sqlite-node`; `sdks/vscode` (extension `sst-dev.opencode`). Core src dirs map 1:1 to the ticket's areas: `agent/ session/ server/ provider/ tool/ permission/ plugin/ lsp/ ide/ acp/ share/ storage/ sync/ background/ worktree/ skill/ command/ mcp/ config/ project/ control-plane/ account/ auth/`.

## 2. Runtime architecture (agent loop)

- **Effect-TS service graph**: every subsystem is a `Context.Service` + `Layer.effect` + `LayerNode.make({service, layer, deps})` node (`agent/agent.ts:441-451`); DI is a static compile-time-ish graph, **not** runtime mounting — no DSH-style unmount/HMR story, but also no privileged core files to patch (still: capabilities are hardcoded services, not config rows).
- **Loop** (`session/prompt.ts` ~1.6k lines, `Interface.loop`): a **task queue** — each iteration pops a task (`subtask` = subagent work, `compaction`, else model step): exit when last assistant finished ≠ tool-calls; per-agent step cap (`agent.steps`, `Infinity` default) with a `MAX_STEPS_PROMPT` assistant prefill injected on the last step (prompt.ts:1178-1281); per-step: resolve tools (`session/tools.ts`), assemble system (environment + AGENTS.md instructions + MCP instructions + skills), run `SessionProcessor.process`, then `continue|compact|break`.
- **Processor** (`session/processor.ts`): maps one LLM stream to durable **parts** (text/reasoning/tool/step-start/step-finish/patch) on the assistant message; captures file **snapshots before** the stream and per step, emitting `patch` parts (hash + files) per step-finish (processor.ts:99-102, 435-470); **doom-loop detection**: 3 consecutive identical tool calls (name + JSON input) → `permission.ask({permission: "doom_loop", always: […]})` (processor.ts:356-380, threshold const); retry via `SessionRetry.policy` with surfaced attempt/action/next status; abort → interrupted-tool cleanup marking parts `metadata.interrupted`.
- **Agent = declarative config** (`agent/agent.ts:35-55` `Info` schema: name, `mode: subagent|primary|all`, permission ruleset, model, prompt, temperature/topP, `steps`, hidden, variant). Built-ins: `build` (defaults + question/plan_enter allow), `plan` (edit deny except plan files, bash ask — the read-only preset *is* a permission config), `general`, `explore` (read-only subagent: grep/glob/list/bash/read/webfetch/websearch allow, all else deny), and hidden utility agents `compaction`/`title`/`summary` (deny-all + fixed prompts) — **auxiliary LLM tasks are agents**. Default ruleset includes `*.env: ask`, `question: deny`, `plan_enter/exit: deny`, `external_directory: ask` + whitelisted skill/truncate dirs (agent.ts:119-136). **`Agent.generate`** LLM-authors a new agent (identifier/whenToUse/systemPrompt via `generateObject`) (agent.ts:368-436).
- **Per-step reminder injection** (`session/reminders.ts`): appends synthetic parts to the last user message per agent (plan-mode notices, etc.) — diverges from DSH's stable-prompt-head discipline.

## 3. Client/server architecture

- **Server** (`server/server.ts`): Effect `HttpApi` — typed route groups (`server/routes/instance/httpapi/groups/`: config, control-plane, control, event, experimental, file, global, instance, mcp, metadata, permission, project, provider, pty, query, question, session, sync, tui, workspace), WebSocket event stream (`websocket-tracker.ts`), CORS opts, basic auth (`OPENCODE_SERVER_PASSWORD`/`USERNAME`, *docs: server*), port fallback 4096→0, **mDNS publish** (`server/mdns.ts`, `--mdns` advertises `opencode.local`, `--mdns-domain`) (server.ts:155-170). `OpenApi.fromApi(PublicApi)` exposes the spec (*docs: server*: "server exposes an OpenAPI 3.1 spec endpoint. This endpoint is also used to generate an SDK").
- **Server-first**: "When you run `opencode` it starts a TUI and a server. Where the TUI is the client that talks to the server" (*docs: server*). `opencode serve` = headless server; `opencode attach <url>` attaches a TUI to a remote server; `/tui` endpoint drives a TUI through the server (used by IDE plugins). One server hosts **many project instances**: per-directory `InstanceState` (`effect/instance-state.ts`), project/worktree/directory registry in SQLite (`project/project.ts`).
- **ACP** (`acp/service.ts`, 1.1k lines): full agent-side ACP — initialize, `authenticate` (custom `opencode-login` method), new/load/list/resume/close/**fork** session, setSessionConfigOption/**Mode/Model**, prompt, cancel — implemented **as a client of its own SDK** (`sdk: OpencodeClient`, service.ts:75-80). DSH's ACP is an automation-only subset.
- **Plugins are clients too** (`plugin/index.ts:143-168`): `PluginInput` hands every plugin an authenticated `createOpencodeClient` (in-process fetch fallback when no server URL) — plugins extend by API calls + hook mutation, not by providing services.

## 4. Provider abstraction

- **Registry** (`provider/provider.ts`, 2k lines): providers sourced `env|config|custom|api`; **models.dev** is the canonical model catalog (`cli/cmd/models.ts` "refresh the models cache from models.dev"; id-normalization comments at provider.ts:378, 849-870). `Model` schema carries `api.npm` (SDK package id), capabilities (modalities in/out incl. audio/video/pdf, interleaved-reasoning fields), **cost with cache read/write + context-tier pricing + >200K override**, limits, release_date, variants, status (provider.ts:1003-1100).
- **Custom providers load npm packages** (e.g. `npm: "gitlab-ai-provider"`, provider.ts:694, 1270); provider **auth is plugins** (`plugin/index.ts:67-86`: Codex, Copilot, Modal, Gitlab, Poe, Cloudflare×2, Azure, DigitalOcean, Snowflake, Xai, Cerebras — OAuth/onboarding in-process); `ProviderTransform.providerOptions` per-provider request transforms; OpenAI-OAuth special-casing (instructions via providerOptions, `store: false`) (agent.ts:386-427).
- **Dual LLM runtime** (`session/llm/AGENTS.md`): default path = Vercel **AI SDK** (`streamText` → `LLMEvent`s); opt-in (`OPENCODE_EXPERIMENTAL_NATIVE_LLM`) first-party runtime `@opencode-ai/llm` (`llm/route` `LLMClient`/`RequestExecutor`; "schema-first LLM core… provider quirks live in adapters") — per-request gate with automatic fallback; both converge on one `LLMEvent` stream.
- **Zen**: first-party hosted gateway (`opencode/<model-id>`, `/connect` + opencode.ai/auth — *docs: zen*). Retry: `SessionRetry.policy` (provider-aware, status events) ≈ DSH Bounded retry. Title/summary models via hidden agents; `experimental.provider.small_model` plugin hook.

## 5. Tools

- **Interface** (`tool/tool.ts`): Effect-Schema params, `execute(args, ctx)` → `{title, metadata, output, attachments}`; ctx carries messages, abort, live `metadata()`, `ask()`; the wrapper enforces schema errors as model-facing `InvalidArgumentsError` ("rewrite the input") and **applies output truncation with spill** (`truncate.output` → `outputPath` in metadata; `tool/truncation-dir.ts`, `Truncate.GLOB` whitelisted as external dir) — ≈ DSH oversized-output spill, mechanism in the tool wrapper.
- **Registry** (`tool/registry.ts:209-249`): built-ins `bash(shell), read, glob, grep, edit, write, task, fetch(webfetch), todo, search(websearch), skill, patch(apply_patch), question, lsp, plan, execute(code-mode)` + `invalid` (error-shaped catch) + plugin tools; **model-conditional selection**: `apply_patch` replaces edit/write on `gpt-*` (non-oss/non-4) models (registry.ts:297-300); websearch gated by provider/flags; `question` only when client ∈ app/cli/desktop; `lsp`/`plan` behind experimental flags. Registry describes subagents into the task tool filtered by permission (`describeTask`, registry.ts:265-278).
- **Shell** (`tool/shell.ts`): **tree-sitter bash + PowerShell parsing** for command analysis; `BashArity.prefix` arity-aware permission patterns; `external_directory` checks; default 2-min timeout; background execution. Edit path has its own staleness semantics (`edit.ts`, `write.ts`).
- **Code Mode**: `packages/codemode` — "Effect-native **confined code execution** over schema-described tools": model writes a JS program; first-party **interpreter** (`src/interpreter`, `stdlib`, `openapi`) with no ambient fs/process/network/module authority; host supplies tools (`CodeMode.execute({tools, code})`). Wired as the `execute` tool (`tool/code-mode.ts`, `describeCodeMode` catalogs MCP tools for it). ≈ DSH Code Mode (run_code); OpenCode confines by interpreter construction, DSH by re-entering the guarded pipeline in a worker thread.

## 6. LSP / editor integration

- **LSP client** (`lsp/`): spawns real language servers from a config'd catalog (`lsp/server.ts`), tracks symbols/workspace symbols/diagnostics (`diagnostic.ts`), `Language` registry; `lsp` tool behind `flags.experimentalLspTool`. Richer than DSH's opt-in 4-op navigation seam; not default-visible either.
- **IDE** (`ide/index.ts`): detects VS Code/Insiders/Cursor/Windsurf/VSCodium via `TERM_PROGRAM`/`GIT_ASKPASS`; `install()` shells `code --install-extension sst-dev.opencode`. Extension source: `sdks/vscode`. ACP for Zed-class editors (§3). The `/tui` server endpoint lets IDE plugins prefill/run prompts through a TUI (*docs: server*).

## 7. Permissions

- **Engine** (`permission/index.ts`): rules `{permission, pattern, action}` ∈ allow/ask/deny; `evaluate` = **findLast** match over merged rulesets (order: defaults → per-agent → user config → session-approved), unmatched → `ask`; pattern targets are tool names, file globs (`read`/`edit`), bash command globs, agent names (`task`), `external_directory`, plus synthetic permissions `doom_loop`, `question`, `plan_enter`, `plan_exit` (agent.ts:119-136; `~` expansion; `permission/arity.ts`). **No OS sandbox** — `packages/containers` is CI Dockerfiles; project "sandboxes" = worktree dirs (`project/project.ts:309` returns worktree as sandbox for non-vcs dirs).
- **Ask/reply** (index.ts:67-167): `ask` publishes `permission.asked` event and awaits a Deferred; `reply` ∈ once | always | reject(**+message → `CorrectedError` feedback to the model**); always persists a session rule and **cascades** to satisfy other pending asks; reject rejects *all* pending asks for the session. Tool-arg correction is native (reject-with-feedback), vs DSH frozen-arguments + one-shot approval.
- **Catalog pruning**: tools whose permission is `deny` at pattern `*` are hidden from the model entirely (`disabled`/`visibleTools`, index.ts:204-219) ≈ DSH `tools.restrict` (deny+refuse), same "one visibility" idea.
- Plan mode: the `plan` agent's deny-edit ruleset + `plan_exit` permission + experimental `plan` tool (`tool/plan.ts`) — plan-ness is permission config, not a logged mode.

## 8. Sessions / state

- **Storage**: SQLite via drizzle (`storage/storage.ts` legacy JSON-file KV + `@opencode-ai/core/database` + `effect-sqlite-node`); messages = rows; **parts** = typed rows (text/reasoning/tool/step/patch/file) with `PartID.ascending()`; assistant messages carry cost/tokens/model/agent/path `{cwd, root}`. Session events over the bus (`bus/`, `event-manifest.ts`, `event-v2-bridge.ts`) with **sequence table** for ordered WebSocket replay (`control-plane/workspace.ts` imports `EventSequenceTable`).
- **Snapshot/revert** (`session/revert.ts`): `revert({sessionID, messageID, partID?})` + **`unrevert`** — file-level undo/redo driven by the patch parts (docs: config "OpenCode uses snapshots to track file changes… undo and revert changes within a session").
- **Compaction** (`session/compaction.ts`, 569 lines): overflow-driven (`isOverflow` on step tokens; `compaction.auto` toggle), runs the hidden `compaction` agent, prunes old summaries, plugin hooks `experimental.session.compacting` / `compaction.autocontinue`; per-message background **summaries** via hidden `summary` agent; titles via hidden `title` agent (first real user message only).
- **Projects/worktrees/workspaces**: SQLite registry (project = vcs root; worktrees with `startCommand`; directories); background job registry with **`promote`/`waitForPromotion`** (`background/job.ts` re-exporting core engine). Fork/resume via ACP + session API.

## 9. Remote / mobile / cloud

- **`opencode serve`/`web` + attach** (*docs: server, web*): basic-auth password, `--hostname 0.0.0.0`, CORS allowlist, mDNS LAN discovery (`opencode.local`). No first-party mobile app in-repo; third-party clients (OpenCode Mobile, KKCode) document `serve` + Tailscale/LAN as the supported path — the OpenAPI server *is* the mobile story.
- **Share** (`share/session.ts`, `share/share-next.ts`): publish sessions to a cloud backend → `opncd.ai/s/<id>` public URLs; manual (default)/auto/disabled; secret-authenticated background sync queue of session/message/diff data; enterprise: console-hosted backend, SSO-gating, self-host (*docs: share*). (A "V2" docs page notes share not yet reimplemented in the in-flight V2 runtime.)
- **Control plane** (`control-plane/`): workspace rows with pluggable **adapters** (plugins can `experimental_workspace.register`), targets `{type: "local"} | {type: "remote", …}`; server middleware **proxies HTTP+WebSocket to remote workspaces** (`server/routes/instance/httpapi/middleware/proxy.ts`); **`sessionWarp`** moves a live session into another workspace over HTTP with optional `copyChanges` (workspace.ts:559-703) — remote execution + session migration.
- **Account/auth cloud** (`account/`, `auth/`): opencode.ai accounts, Zen gateway auth.

## 10. Plugins / extensions / skills / commands

- **v1 plugins** (`plugin/index.ts`, `plugin/loader.ts`, `packages/plugin`): plain JS functions `(input) => hooks`; loaded from `plugin_origins` config (npm specifiers; auto-discovered `.opencode/plugin(s)` dirs, config.ts:439-476); loader stages install/load/compatibility/entry with errors surfaced as session errors; deterministic sequential hook order; `dispose` finalizers; hooks = `chat.message/params/headers`, `permission.ask`, `tool.execute.before/after`, `tool.definition` (mutate tool schemas!), `command.execute.before`, `shell.env`, `event` (all bus events), `config`, plus `experimental.chat.{messages,system}.transform`, `experimental.text.complete`, `experimental.provider.small_model`, compaction hooks (`packages/plugin/src/index.ts:234-334`). Plugins can also register tools, providers/auth, and **workspace adapters**. `flags.pure` disables all external plugins (clean-room mode); `flags.disableDefaultPlugins` kills internal ones.
- **v2 plugin API** (`packages/plugin/src/v2/`): Effect-based, scoped registrations with `hook`/`reload` and **domain transforms** (agent/catalog/command/skill/…) where OpenCode "rebuilds the domain… from fresh state… in registration order" (`v2/effect/README.md`) — a Cordis-shaped convergence (reversible, rebuild-on-change) still marked experimental.
- **Skills** (`skill/discovery.ts`): filesystem skills + `skill` tool ≈ DSH filesystem skill discovery + progressive disclosure. **Commands** (`command/`, `config/command.ts`): custom slash commands as markdown/JSON (`~/.config/opencode/commands/`, `.opencode/commands/`), template `$ARGUMENTS`, per-command agent/model. **Agents as files**: `{agent,agents}/**/*.md` + frontmatter (config/agent.ts:13-47; legacy `modes/*.md`). **Instructions**: AGENTS.md/CLAUDE.md etc. + config `instructions` globs (session/instruction.ts).
- **MCP** (`mcp/index.ts`, 1k lines): official SDK client; stdio+remote, **OAuth provider + callback** (`mcp/oauth-provider.ts`), browser-assisted auth (`mcp/browser.ts`), catalog of known servers, tools+resources (resource attachments incl. PDF/images, 10 MiB cap — prompt.ts:65-72), `tools_changed` re-sync; capabilities: roots answered, **sampling/elicitation/tasks disabled** with open issue links (index.ts:39-50). Permission integration: `session.permission` ruleset per session gates MCP tools; `Permission.visibleTools` prunes denied ones from code-mode catalogs too.

## 11. Surfaces (TUI / web / desktop / SDK / bots)

- **TUI** (`packages/tui`): SolidJS on `@opentui/solid` (sst's terminal renderer) — command palette, dialogs (agent/model/provider/session/skill/**stash**/tag/mcp/status/retry-action…), consumes `@opencode-ai/sdk`; plugins can extend the TUI (`packages/plugin/src/tui.ts`, `plugin/tui/runtime.ts` in core).
- **Web** (`opencode web`, `packages/app`): browser client with e2e/playwright perf harness; **Desktop** (`packages/desktop`): Electron (beta); **VS Code** (`sdks/vscode`); **console** (`packages/console`): team console; **session-ui** shared components.
- **Headless**: `opencode run` (message/prompt-file args, `--command`, `--format json`); **service daemon**: `packages/cli` `service start/stop/restart/status/password`. **Bots**: `packages/slack` Slack bot (Socket Mode, threaded); GitHub agent — `opencode github install/run` (GitHub App + mock events; `cli/cmd/github.handler.ts`) + `opencode pr <n>` (fetch PR to worktree, run agent on it).

## 12.5 Cross-cutting observations for synthesis

- **Config priority ladder** (config.ts:273-545, docs: config): defaults → global `~/.config/opencode/opencode.json[c]` → project `.opencode/opencode.json[c]` (walked up) → **remote org config (`.well-known/opencode`)** → **managed dir** → **macOS MDM `.mobileconfig` (highest, not user-overridable)**; `$schema` seeded into the global file for editor completion; flags > config. Enterprise governance is a config-source, not a deployment wrapper.
- **Symmetric absences (both harnesses)**: cross-session memory/learning (D7), cron/calendar scheduling (D9), persistent agent teams (D8), browser/screen control (D12), canvas/mini-apps (D18), multi-node clustering (D11). Asymmetric DSH-only: OS confinement, goals, Ralph/workflows, event-sourcing invariant, client plugin roster, KV-cache discipline. Asymmetric OpenCode-only: pattern-permission engine w/ persistent grants, share URLs, remote workspaces/warp, Slack/GitHub channels, mDNS, managed config, native binary distribution, models.dev catalog.
- **Two "one server" meanings**: DSH web host serves many *sessions* of one composition; OpenCode server hosts many *project instances* (per-directory `InstanceState`, per-instance plugin hooks, project rows) — compare on multi-tenancy axis, not session count.
- **Auxiliary LLM tasks are first-class agents**: compaction, titles, summaries (and `Agent.generate`) all run through the same agent-config machinery with deny-all rulesets — a uniform "hidden agent" pattern DSH implements as dedicated services (`ctx.compaction`, projections).
- **Prompt-variant files ship in-tree** (`session/prompt/*.txt`, incl. `beast.txt` with resume/continue todo-completion instructions) — persona is a versioned asset here, vs DSH's prompt-section assembly service.
- **Dogfooding**: repo root `AGENTS.md`/`CONTEXT.md` + `.opencode/` dir — developed with OpenCode itself, same as DSH's postmortem/skills culture signal.
