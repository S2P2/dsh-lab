# OpenWorker: Andrew Ng's governed desktop coworker — architecture & capability profile

**Verdict.** OpenWorker ([andrewyng/openworker](https://github.com/andrewyng/openworker)) is the inverse bet of DSH: where DSH makes *composition* the architecture (everything a swappable Cordis plugin), OpenWorker makes *governance* the architecture — a single opinionated Python TurnEngine wrapped in a three-tier control system ("hard floors · earned-autonomy ladder · audited provenance") whose permissions module refuses privilege escalation *by construction* (the agent cannot edit the files that govern its own permission engine). Its second distinctive axis is **product postures DSH deliberately doesn't ship**: a supervisor-style desktop shell (Tauri) that owns a Python sidecar server; a connector layer that turns the agent into a *two-way* resident of Slack/email/calendar, not just a tool caller; scheduled automations with catch-up replay and task-scoped standing permission rules; an unattended mode that parks every ask in a human Inbox instead of acting; and a cross-session memory subsystem. Underneath, it is far less orthogonal than DSH: no plugin/extension architecture at all, one hard-coded agent loop, catalogs instead of seams — a "working reference for what aisuite can carry," per its own README. Where DSH says "absent by design scope," OpenWorker ships the missing quadrants (memory, scheduling, channels, browser/fetch) as first-class product features; that pairing — DSH's absent dimensions all present-but-unified-under-governance — is the headline finding for the capability map.

## 1. Positioning & declared surface

An "open-source AI coworker that lives on your desktop and delivers **finished work**, not just chat" (README.md:9). Local-first BYOM (14 named providers + Ollama local, README.md:79); privacy stance: "the only cloud piece is a small service that brokers OAuth handshakes for connectors" (README.md:85). Ship-first posture: specialist Security coworkers with personas, scanners, and fix-PR workflows (README.md:9,35). Governance claim, verbatim: "Governance is the architecture, not a plugin — the agent can't grant itself new permissions, and no prompt can talk it past a gate" (README.md:59). v-beta; macOS Apple Silicon signed/notarized + auto-update; Windows unsigned (SmartScreen warns), signing "in progress" (README.md:16-21).

Product surfaces inventoried from the REST route table alone (`coworker/server/app.py:170-2832`): sessions/messages, approvals via `/v1/inbox`, automations CRUD + run + finalize, MCP CRUD/OAuth, connectors connect/disconnect/accounts/allow-lists, memory CRUD + settings, skills upload/install, personas install/export + cloud gallery, workspace trust/roots, artifacts list/read/reveal, board/team-chat/journal, providers CRUD + Codex-subscription sign-in, web-search proxy, browser state/screenshot, settings (auto-approve, compaction, pdf, nav-layout, scratch-base…), and `/v1/chat/completions` (OpenAI-compatible endpoint served by the local server).

## 2. Desktop/runtime separation

- **Two-process shape**: native shell (React UI + Rust Tauri shell) ⇄ always-on local agent server (Python/FastAPI, `coworker/server/app.py`) — README diagram (README.md:46-55). Dev mode runs them separately (server on :8765, Vite on :1420); production bundles the server inside the Tauri app.
- **Sidecar supervision** (`surfaces/gui/src-tauri/src/lib.rs:4-175`): shell picks a **free localhost port** (never clashing with a hand-run server on 8765), spawns `openworker-server` as a managed child, and **injects the sidecar HTTP/WS addresses + a per-launch auth token before any page loads**; the server keeps running with window close (tray-resident) and only tray→Quit stops it; child killed on exit ("orphaned servers have bitten us before"). Launch token: standalone server writes `<state-dir>/sidecar-<port>.token` (user-only file the dev UI reads; direct API callers send `X-OpenWorker-Token`), while the desktop app uses an **in-memory** launch token never written to disk (README.md:109-112).
- **Environment faithful spawn** (lib.rs, OPE-83): production sidecar env comes from asking the user's login shell once at spawn (5s timeout, chatty-profile-safe parsing, well-known-dirs PATH repair) so GUI-launched servers see the terminal environment (gpg, git credentials, nvm).
- **Keep-awake hold**: the shell holds `caffeinate` (macOS) / Windows execution state during runs (lib.rs:36).
- **Bundling/auto-update** (`packaging/`): PyInstaller **onedir** sidecar shipped as Tauri `resources`; legacy onefile slot kept; `make_update_manifest.py` feeds the Tauri updater; build scripts `build_dmg.sh` / `build_windows.ps1`.
- **Voice input**: separate Rust STT sidecar crate (`stt/src/lib.rs`).
- Contrast with DSH: DSH separates host plane / per-session agent plane inside *one* Node process with a plain `node:http` carrier, deliberately **no auth** (LAN-trust-fence only), and offers browser-first with optional Electron. OpenWorker authenticates even its own localhost traffic, matches shells-per-machine (one server, many sessions), and owns process lifetime from the shell.

## 3. Backend & agent-engine architecture

Python package `coworker/` ("Agent coworker platform — provider-agnostic agentic coworker runtime", pyproject.toml). Console entry points: `openworker`, `openworker-server`, `openworker-connectors`, `ocw` (teams CLI).

- **TurnEngine** (`coworker/engine.py:77`) — one concrete async generator loop per session (no swappable driver): `run()` → `_loop()` streams `ASSISTANT_DELTA`/`REASONING_DELTA`/`ASSISTANT_MESSAGE`/`TOOL_*`/`PERMISSION_REQUIRED`/`COMPACTING`/`INTERRUPTED` events; capped at `max_iterations` (default 12, config.toml:9); steering queue injected between iterations (engine.py:271,1866); interrupt resolves mid-stream/mid-tool/mid-await while guaranteeing every pending tool_call gets a result so history carries no orphans (engine.py:241-247).
- **Surfaces as injected callbacks**: the engine knows nothing about GUI vs Slack vs TUI — the SessionManager hands it `approver`, `question_asker`, `plan_approver`, `team_approver`, `items_approver`, `directory_requester`, `tool_requester`, each returning a typed outcome; surfaces that can't prompt get no-op behavior the agent is told about (engine.py:86-153). This is a narrower seam than DSH's ctx.services but same idea: engine/UI decoupling.
- **Hygiene details of note**: mangled (unparseable-args) tool calls detected and sanitized rather than crashed on (engine.py:2026-2045); partial assistant output survives stop/error (engine.py:467-521); output-token-limit flag changes the diagnosis given for malformed calls (engine.py:230-232); parallel-safe tool classification enables concurrent dispatch (engine.py:849).
- **Agents/personas**: fixed agent types Chat (no tools), Code (single-root dev surface), Cowork (multi-root knowledge-work surface composed from a vetted catalog, `agents/cowork.py`); on top, **personas** are data: `manifest.md` (YAML front-matter: group/id/name/icon/tagline/requires_folder/**subagents**/tools/connectors/skills/**recommended_models**/**default_permission_mode**/recommends-with-tiers) + body instructions + bundled `SKILL.md`s (example: `personas/builtin/security/manifest.md`). Registry resolves persona → Agent; third-party persona loading has an install-time **capability consent flow** (`personas/loading.py`: `consent_summary`). Persona gallery install/export via the optional cloud account.
- **Sessions/state**: sessions and messages persist in SQLite (`coworker.db`), sessions carry unattended flags separately (`unattended.json`); engine messages survive reload; durable resume re-raises unanswered tool prompts on restart (engine.py:396-412; `test_durable_resume.py`). Compaction (OPE-27) triggers at min(0.8×context window, 250k tokens): LLM structured summary + mechanically extracted working state, newest 25% verbatim, **persisted transcript untouched** (compaction.py:3-10,21-29) — i.e., raw-history preservation with a replaced outbound view, philosophically close to DSH's derive-messages-from-log, implemented more simply. Context overflow recovery force-compacts and continues, progress-guarded to terminate (engine.py:489-500).
- **Session environment preamble**: `environment.py` pre-computes pwd/uname/git-status/git-log into the system prompt to save discovery calls, labeled point-in-time.

## 4. Governance: the permission stack (the core of the design)

Five-way risk classes — READ / EGRESS / WRITE_LOCAL / EXEC / EXTERNAL ("side effects off the machine — the unattended Inbox hook"), declared once per tool, effective risk = user override **that may tighten but never loosen** built-ins or connector-catalog writes (strictness ladder prevents downgrading; fail toward EXTERNAL via aisuite `requires_approval` metadata; `risk.py:18-110`). EGRESS includes `web_fetch`, `web_search`, `browser_open_url`, and contact-enrichment lookups, each with written exfiltration reasoning (risk.py:29-54).

**Modes** (`permissions.py:213-229`): `discuss` (read-only chat) · `plan` (read-only + planning contract) · `interactive` (default ask) · `bypass-approvals` (full access *minus floors*; renamed from `auto` because floors still apply — README's "full access" would be "a false promise", permissions.py:219-223) · `auto-approve` (LLM reviewer judges cards) · `custom` (+config `auto_allow` tool set).

**Authorization ladder** per consequential call (`engine.py:1079-1350 _authorize`): evaluate → floors may force `human_only` → downloaded-file floor (below) → reviewer consult iff `needs_user ∧ ¬human_only ∧ attended` → else PERMISSION_REQUIRED card enriched with provenance fact, `standing_target` eligibility, `readonly_ok` classifier verdict, and per-tool extras (which provider web_search hits) → await injected approver → outcomes recorded with origin (`user`/`reviewer`/`bypass`/standing-rule) consumed into TOOL_FINISHED and a **`_display` sidecar carried on the tool message: persisted and shown after reload, stripped before anything reaches a provider** (engine.py:177-182 — the exact inverse of DSH's "model-visible ⇒ logged": here "logged ⇒ not necessarily model-visible").

**Hard floors** (run before every mode/allowlist; no click in-flow can grant them; permissions.py:93-131,337-404):
1. **Self-protection floor** — no write/exec may touch the files governing the permission system itself (config.toml, risk_overrides.json, workspace_trust.json, unattended.json, coworker.db ["saved always-allow grants"], secrets.json, inbox_routing.json); rationale comment: "approve one ordinary-looking command, it quietly appends to the rule file, every future session is more permissive."
2. **Deferred-execution in-project files** — `.git/hooks/`, `.github/workflows/`, `.gitlab-ci.yml`, `.vscode/tasks.json`, `.coworker/` stay writable but every edit is routed to a human ("an edit here is a deferred command").
3. **Persistent-authority floor** (OPE-117) — `save_skill`, `create/update/delete_scheduled_task` are human-only: their effects land after the authorizing conversation ends, so "the person who bears it is not in the room."
4. **Downloaded-file floor** (OPE-114 §1) — running a file the agent *downloaded* this session forces a person (fetch-then-execute); agent-*written* files are not floored ("write this script and run it" is ordinary work) but travel as a provenance fact to card and reviewer (`provenance.py`, engine.py:215-222).
5. **Unscopable-write fails closed** — if patch parsing can't locate the write path, decision is human_only (permissions.py:356-368).

**Earned autonomy, graduated** (the ladder of README tier 2): one-off approve → session grants minted by "always allow this X" clicks (tool/command-exact/domain-suffix/readonly-classifier, permissions.py:475-496) → config-prefix command allowlist with serious parsing hygiene: compound commands split per-part (`git status && rm -rf ~` fails), opaque constructs (`$(`, backticks, redirection) disqualify, arg-executors (`xargs`,`sudo`,`ssh`,`docker`,`npx`…) and interpreter inline-code flags ineligible, `-exec/-delete` flags rejected, word-match not text-match (permissions.py:578-623; readonly.py adds a conservative read-only-command classifier with pipelines/per-subcommand git guards plus **read-target extraction** scoping what a granted command may *READ* against roots, readonly.py:161-251, OPE-130) → **task-scoped standing rules** `{tool: {targets}}` owned by an approved automation, external-risk-only, target-exact, audited on every use ("allowed by standing rule: slack_post_message → C123", permissions.py:260-278,454-465). Deliberate subtlety: in auto-approve mode, in-flow session grants are *not* honored — the judge sees them anyway (spec §1.5, permissions.py:411-431).

**The Auto-Approve reviewer** (`reviewer.py` + engine.py:860-1005,1036-1078): a second model call using **the session's own model** ("if it's trusted to drive the agent, it's strong enough to review it", reviewer.py:306-313), one action per request, verdicts allow/deny/unsure with asymmetric-cost instruction ("a wrong allow deletes work; a wrong unsure costs one click"); fail-closed — every parse defect/timeout/error becomes `unsure`⇒human; **never shown untrusted content**: input = instructions + known-world (folders/remotes) + user's own verbatim clipped messages (ask_user answers tagged as replies-to-agent-question, agent-authored text excluded) + proposed action — "the attacker can address the agent, never the judge" (reviewer.py:16-19); deny returns a terse non-diagnostic message to the agent (anti-oracle) while the full reason goes to user+audit (reviewer.py:152-161); consecutive denials trip a **circuit breaker** (non-cumulative streak) that pauses the reviewer with a persisted notice (engine.py:170-176,1175-1190); usage metering counts cache reads correctly; a **shadow mode** records what the reviewer *would* say on every real approval card for offline eval (engine.py:183-189; committed eval reports `reports/reviewer-eval-2026-08-{13,18}-*.md` across GPT/GLM/Kimi models).

**Unattended mode**: changes *where the human is reached*, not autonomy — asks park in the Inbox; resolution is once, idempotent `(session_id, tool_call_id)`, answerable from app/Slack/composer; blocking items persist and are reconciled on restart without double-prompting (inbox.py:8-12,77-79,334-383).

**Workspace trust** (`workspace_trust.py`, manager.py:377-441): repository-supplied `.coworker/config.toml`, `allowed_commands`, and MCP configs are honored **only for trusted workspaces** — cloning alone must not define processes that run on session open (`mcp/config.py:57-65`). `roots.py` supports multi-root per-session folder grants (read-only roots enforce read-scoping).

**Honest limits, stated in code**: shell-text protected-path matching "stops accidents and casual attempts, not a determined adversary (that needs the OS sandbox)" (permissions.py:528-534); the readonly grant is "a user-elected convenience … not a sandbox" (readonly.py:18-19). There is **no OS confinement layer** anywhere — enforcement lives entirely in the decision layer (plus egress URL guarding in `web/guard.py` for model-chosen URLs, defending against prompt-injected fetch targets).

## 5. File/terminal access

Tools: `files.py` (read/write/replace/apply_patch/apply_unified_diff — the four WRITE_TOOLS), `directories.py` (multi-root adds via in-conversation `request_directory` → DIRECTORY_REQUESTED prompt → live grant application, engine.py:128-131,1732), `search.py` (grep-like), `git.py`, `shell.py` (`run_shell`, EXEC class; **foreground**, approval-gated; interrupt hooks kill running commands, engine.py:110-112), `subagent.py`, `ask.py`, `plan.py` (`propose_plan` flips the live PermissionEngine out of plan mode), `todo.py` (rendered as a Progress panel — see persona manifest line 43), `toolreq.py` (`request_tool`: agent-triggered install-with-consent, engine.py:132-135), plus web fetch/search and browser (optional Playwright extra; `browser_open_url` classified egress with an address guard; screenshot/state/close exposed over REST for the GUI, app.py routes). No PTY API for the model; no code-execution-in-workspace primitive like DSH Code Mode (`run_code` absent).

## 6. Connectors, messaging channels & cloud

Three distinct layers share the word "connector":

1. **SaaS integration catalog** — data-driven descriptors (auth method, pasted fields, validate-by-real-API-call returning bot identity) drive a setup wizard; tool definitions are generated per connector with declared target args, approval requirements, and per-tool user toggles (`connectors/descriptors.py`, `connectors/tool_defs.py`, manager.py:1571-1637). Named services in code/catalog: Slack, GitHub, Gmail, Google Calendar, HubSpot, Outlook, Jira, Notion, Linear, monday.com … ("25+", README.md:71). Multi-account handled generically (accounts/default/endpoints per service family: `gmail_accounts`, `gcal_accounts`, `github_installs`, `hubspot_portals`, `slack_addr`).
2. **Messaging platform adapters** (`connectors/base.py`) — inbound/outbound adapter contract (`BasePlatformAdapter.connect/send/handle_message`), `SessionSource` identity + opaque reply-handle targets `platform:chat_id[:thread]`, `MessageSource` display-sidecar stripped before provider visibility, button-click InteractionEvents, and an allowlist-gated `gateway.py` living inside the always-on server (closed by default; dropped senders' messages are **parked** for one-step allow-and-deliver, `parked.py`). Two Slack inbound transports: Socket Mode or the **managed cloud relay** (`relay_client.py`), team-qualified handles for multi-workspace. Mentions (`@OpenWorker`) open desktop sessions with replies posted back as thread messages (README.md:70).
3. **OpenWorker Cloud (optional)** (`cloud.py`) — sign-in + **managed one-click OAuth connectors**; "the only cloud piece … brokers OAuth handshakes" (README.md:85); fully functional signed-out via manual tokens; also hosts the persona gallery and (route `/v1/cloud/telemetry`) opt-in telemetry. Slack approval-owner routing (`POST /v1/connectors/slack/approval-owners/*`) lets inbox asks be answered by designated owners in-channel; the codebase retains fake-Slack test infra (`testing/fake_slack/server.py`).

Connection effectiveness is layered per-persona + per-session over global connection state (`connections.py`: default-if-present/inherit rules; persona manifests carry `connectors: [...]` and `recommends: [{connector, reason, tier}]`).

## 7. MCP

Standard Claude-Desktop-compatible `mcpServers` JSON, layered global + trusted-workspace (**global wins name clash**; untrusted repos' MCP config never read — executable-provenance argument, mcp/config.py:55-109). Transports stdio + http(s)/sse/streamable; `${VAR}` refs resolved at load via SecretStore; per-server include/exclude tool filters and `requires_approval: true` default; HTTP servers support **OAuth 2.1 + PKCE with Dynamic Client Registration**, tokens held in the SecretStore, callback at `/mcp/oauth/callback` (mcp/config.py:26-42; routes in app.py). Manager handles connect/signout/reload lifecycles with failure-notification throttling (manager.py:1340-1569). vs DSH: same bridge concept (tools become `mcp__server__name` style) but DSH ships no MCP OAuth, no workspace-provenance gate, no per-server tool include/exclude.

## 8. Memory

SQLite-backed `MemoryItem` store scoped `global | workspace | session` (session scope deliberately dead-code), keyed by workspace path (memory/base.py, sqlite_store.py). Injection is **build-time wholesale**: global + this-workspace memories render into system instructions; above 8,000 chars it flips to index mode (newest 10 full, rest one-line summaries fetched via `memory_read`) (memory/base.py:71-136; agent.py:404-414, cited by extraction pass). Agent tools `remember/memory_read/memory_update/memory_forget` announce writes (undo hook); Settings toggle disables the subsystem mid-conversation (kept-but-inert); user-authored `user_rules` text is injected **above** memories and "outranks" them (memory/settings.py). This is the DSH-absent quadrant D7 made into a shippable feature — simple, visible, revocable.

## 9. Automation / scheduling / wake

- `ScheduledTask`: title/instructions/schedule/workspace/thread, own continuable run sessions (`__task__<id>`, `__run__<run_id>`), cron(5-field, croniter-validated)+timezone or one-shot `fire_at`; model converts natural language to cron (`automation/tools.py:24-28`); counters/max-runs; unread marks (`seen_runs_at`); notify flags (models.py:23-143, extraction pass).
- Executor: in-process asyncio loop ticking every 30s inside the always-on server, skip-on-overlap guard, **catch-up tick replays missed fires once at startup** — survives restarts as data (SQLite `scheduled_tasks`/`task_runs`), never as out-of-process timers; scheduling therefore requires the app running (enable Launch-at-login) (scheduler.py:1-94; README quickstart states the same).
- Runs inherit **standing rules**: approvals previously granted on write-class actions during attended setup crystallize into `{tool: {target}}` allowlists owned by the task (models.py:39-61; §25); unattended escalation rides the normal Inbox; completion notifications land in-app with full transcripts.
- **Selfwake**: sessions can suspend themselves via `sleep_until`, `wake_on(job)`, `wake_on_event(webhook)` records consumed by the same tick loop (selfwake.py) — agent-initiated deferred resumption, no DSH counterpart.

## 10. Deliverables generation

Per-session scratch directory auto-provisioned under a configurable base (manager.py:460-512); artifacts surface = `/v1/sessions/{id}/artifacts{,/read,/reveal}` (reveal = Finder/Explorer show-in-folder); temp workspaces can be promoted ("save as project"). Personas encode a delivery protocol: end with a finished file, reference it in chat as `[Security review](artifact:reports/security-review.html)` (scratch-path protocol link the GUI renders and opens in built-in viewers for documents/spreadsheets/images/PDFs — quickstart doc: "The built-in viewer previews documents, spreadsheets, images, and PDFs without leaving the app"); PDF ingest falls back to local rendering for providers lacking inline-PDF parts (`pdf_support.py`, providers/matrix.py:31-39). DSH has a deliverables *row* (`client-ui-deliverables`) but no artifact-link protocol, no managed scratch/project promotion, no viewers.

## 11. Model/backend abstraction

- Built **on aisuite** (same owner): unified chat-completions + agents/toolkits/MCP layer; OpenWorker describes itself as "a working reference for what aisuite can carry" (README.md:129-133).
- Local registry: `providers/{base,registry,capabilities,matrix,router}`. ProviderRouter dispatches on `provider:model-string` prefixes (e.g. `ollama:llama3.3`, reseller "ugly ids" like `together:zai-org/GLM-5.2`) to lazily-built clients from SecretStore profiles (router.py docstring). Native clients exist for OpenAI (+Responses API variant), Anthropic (prompt-cache aware), Gemini, Vertex, Bedrock, plus **Codex-subscription OAuth sign-in as a provider** (`codex_provider/codex_auth`).
- Curated model matrix: deliberately small, hand-verified entries mapping full routed ids → display label + capabilities(tools/vision/pdf/parallel/streaming) + verified context windows for the GUI fill-meter; custom strings allowed at user's risk with heuristic capability probes (`capabilities.py`) (matrix.py:1-80).
- Per-session live model switching; per-turn model riding events; usage objects (incl. cache_read/write counted honestly — a 1,400-token cache-read call misreporting as "16 in" is called out as a bug they fixed, reviewer.py:173-179).

## 12. Multi-agent: subagents, teams, board, journal

Personas may declare `subagents: true`; a minimal delegation tool exists (`tools/subagent.py`) — far shallower than DSH's continuation/mailbox/jobs machinery. The heavyweight mechanism is **teams**: a lead session decomposes work via `propose_work_items` onto a shared **board**; user approval of the staffing gate (`propose_team`) pre-spawns member sessions; members coordinate via a team chat dialect; a heartbeat/tick drains member turns with lead backstop digests (manager.py:1688-2359). Architecturally notable: **the board is a projection of an append-only team event log**, not the database of record (`teams/model.py` docstring), and a **BoardDialect** seam abstracts "where the board lives": LocalDialect (SQLite) vs RemoteDialect speaking the `/v1/board` HTTP API — i.e., boards can be shared across machines through the same server routes (teams/dialect.py). A separate case-keyed **journal** survives teams/archived boards, tracking investigations across them (teams/journal.py). This is the closest structural cousin to DSH's experimental agent-team CAS DAG, but productized and with a remote-dialect twist DSH lacks entirely.

## 13. Absence is data (OpenWorker lacks, DSH has)

No extension/plugin architecture of any kind (capabilities are import-time modules; the only user extension points are personas/skills/MCP/connector-descriptor *data*); no capability-seam notion, no per-session composition, no swappable implementations anywhere except the provider registry; no Code Mode / programmatic tool orchestration; no workflow scripts, goal rounds, Ralph loops, jobs registry, typed event bus with interception waterfalls, per-agent scope registration/shadowing, runtime invariants, OTel telemetry seam, plan-mode logged-state machine (a plan proposal exists but is a single gated step), OS confinement runners, filesystem freshness guards (write-intent), KV-stability-as-discipline outside the reviewer prompt (though the code is consistently cache-aware), LSP, embedding SDK, or headless exit-code contract. Skills exist as a store with REST upload/move (`skills/store.py`, 568 LOC) but no layered-root discovery order documented as a priority rule.
