# Agent Harness Capability Map — consolidated across the cohort

**Baseline for: [Wayfinder: Agent harness capability map](https://github.com/S2P2/dsh-lab/issues/11) · synthesis of [#30](https://github.com/S2P2/dsh-lab/issues/30)**

- **Compiled:** 2026-08-30, from 18 completed profiles (17 external harnesses + the DSH baseline) and 2 verification follow-ups, every one pinned to a primary-source SHA (index in §7); post-synthesis extension profiles #19–#20 folded in via §8. Per-cell authority lives in the profile notes; this map **deduplicates, normalizes disagreements, and consolidates the DSH opportunity inventory**.
- **Vocabulary:** *Capability* = user/agent-visible behavior, independent of mechanism. Classifications vs DSH: **Equivalent** · **Packaging gap** (capability reachable by composing/configuring shipped DSH pieces, but nobody ships the package) · **Plugin opportunity** (needs new plugin code at an existing seam — seam named) · **Core gap** (needs host/runtime substrate DSH lacks) · **Not applicable** (philosophy/SaaS contrast, not a gap).
- **Grid notation (§2):** ✓ shipped/strong · ◐ partial / provisional / in-flight · ✗ absent. Cohort columns are as-of each profile's pin date (§7); fast movers are flagged in §6.

## 1. What the cohort is

Nineteen systems — seventeen cohort profiles plus two post-synthesis extensions (§8) — deliberately heterogeneous: productized personal assistants (OpenClaw, Hermes, nanobot), governed desktop coworkers (OpenWorker, Eigent), research fleets (UFO³, NemoClaw+OpenShell), multi-repo platforms (OpenHands), server-first coding agents (OpenCode), closed-source standard-setters (Claude Code), open platforms converging on DSH's shape (Codex, Pi mid-flight), editor-natives (Cline, Goose), a multi-user cloud OS (Cloudflare OS), and a Rust Codex fork (OIX/Workstation). No cohort member is a Cordis-style runtime-composition kernel; **DSH's everything-is-a-plugin tree with typed seams is architecturally unique in this set**, with Pi's in-flight `AgentHarness` rewrite the closest independent convergence.

## 3. DSH opportunity inventory (deduplicated, evidence-backed)

Ordered by cohort consensus. Each record: capability — sources — classification — boundary — why it merits investigation.

> **Post-review verification (2026-08-30).** The owner challenged several calls against DSH's *plugin ecosystem* — a layer this map had not audited, because profiles compared other harnesses' shipped capabilities against DSH's **core repository**. That was a methodological blind spot for a composition-kernel harness whose thesis is that capabilities come from the ecosystem. Live registry verification (GitHub `dsh-plugin` topic) corrected three calls, marked inline below as *[updated]*. Two registry queries were rate-limited (model-router/catalog, auto-approve reviewer variants) — absence there is **unverified**, not asserted.

### Core gaps (host substrate required)

1. **Cross-session memory pipeline** — CC, Codex, OpenClaw, Hermes, nanobot, Agent Zero, OIX (7 independent implementations; Codex's two-phase lease + git-baselined workspace is the reference mechanism). *[updated 2026-08-30: reclassified Core gap → **Plugin opportunity, demonstrated** — mnemon ★532, dsh-memory-connect, dsh-native-memory, dsh-evolve, dsh-plugin-recall all ship cross-session memory on DSH seams (`ctx.llm`, `ctx.sessionQuery`, storage domain, per-turn system-prompt injection). File-convention memory (a MEMORY.md the agent maintains) needs no plugin at all — Cline's Memory Bank was classified "convention only" for exactly this reason. The surviving core residue is narrow: consolidation that runs with no session live, i.e. the always-on slice of #3.]* *(§8 post-synthesis: +thClaws markdown+KMS+`/dream`, +Open WebUI per-user layered memory → **9 of 19** cohort shippers; both reinforce the plugin-demonstrated call — files+bus mechanisms, demand compounding.)*
2. **Network-egress policy (domain/socket) in the sandbox** — Codex, OIX, NemoClaw. Why: filesystem-only confinement is DSH's narrow waist; all three treat network as a first-class policy surface. Extends D13 runners, not plugins.
3. **Always-on automation host (cron/calendar + channel presence)** — OpenClaw, Hermes, nanobot, Agent Zero, Cline, OpenHands, Goose(in-process counterexample). *[updated 2026-08-30: narrowed by dsh-timer-agent ★4 — a host-resident cron engine + jobs board that fires real agent sessions on schedule (continuing a pinned session or starting fresh). While a host process runs, scheduled session firing is plugin-reachable; the surviving core/deployment residue is **service lifecycle** — running the host unattended as a system service (boot-start, supervision), with channel presence (inbound webhooks at arbitrary times) still needing the same substrate.]* Why the residue matters: unattended operation without a manually-started host. (Session-scoped scheduling alone remains plugin territory — see #8.) *(§8 post-synthesis: +thClaws native launchd/systemd daemon, +Open WebUI RRULE owner-automations — both confirm the service-lifecycle residue framing.)*
4. **Live remote session fabric** (relay/attach/warp/paired nodes) — Codex, OpenCode, OpenClaw, CC, Cline. Why: multi-client attach and cross-host session takeover break single-host log assumptions; needs host-level session ownership model.
5. **Interactive desktop/computer-use substrate** — UFO, Agent Zero, Eigent, OIX; Cline's mid-migration stub is the counter-signal. Why: media/input injection is below DSH's tool pipeline; browser-only variant is plugin-reachable (#9).
6. **Multi-device orchestration fabric** — UFO Galaxy/AIP, Cloudflare OS object-capability mediation, OpenHands cross-instance leases. Why: DSH agents are single-host; device graphs and mediated resource capabilities have no seam.

### Plugin opportunities (existing seam, new code)

7. **LLM-assisted approval/review layer** — goose (judge + adversary), CC (classifier auto-mode), OpenHands (risk-prediction ensemble), Codex (Guardian), OpenCode (doom-loop). Boundary: `tools/pre-execute` waterfall + `ctx.approval`. Why: five independent stacks converge on detection-in-front-of-approval; zero core change needed in DSH. *[clarified 2026-08-30 after owner review: DSH already ships the approval **plumbing** — sandbox modes switchable mid-session via permission presets, `ask_user_question`, one-shot escalation, approval-policy switch notices — and the map scores that Equivalent. The opportunity is the missing **responder**: an LLM that auto-approves low-risk calls and flags/denies high-risk ones without a human in the loop, as CC auto-mode and Codex Guardian do. No such plugin found in the registry (one variant query rate-limited — unverified absence).]*
8. **In-process scheduling/cron recipes** — goose `tokio_cron_scheduler` recipes, Cline agenda queue mechanics. Boundary: `dsh-schedule`-style plugin + `agent/*` events; stays session-scoped (the always-on half is core gap #3). *[updated: dsh-timer-agent ★4 already demonstrates scheduled session firing from a host-resident plugin — the recipe/harnessing layer is ecosystem-active.]*
9. **Browser automation tool** — Agent Zero (DOM refs, BYO browser), UFO (action layer ships as MCP servers). Boundary: `ctx.tools` + `ctx.subprocess` + `ctx.attachments`, mounting UFO-style MCP action servers through the existing bridge. Why: lets DSH reach the web without a desktop substrate (core gap #5 stays separate). *(Registry check 2026-08-30: no browser plugin found — open.)*
10. **Full MCP client surface** — goose, Codex, Cline, OIX (resources, prompts, elicitation, sampling, MCP Apps UI). Boundary: `dsh-mcp-client` + typed events. Why: DSH's bridge is deliberately tools-first; the cohort treats the rest of MCP as table stakes.
11. **Checkpoints / per-step snapshots / rollback** — CC, OpenCode, Cline, Pi. Boundary: `fs/*` events + session projections. Caveat: shell-command effects bypass `fs/write-intent`, so snapshot completeness needs the guarded pipeline — record as open question. *(Registry check 2026-08-30: no checkpoint plugin found — open.)*
12. **Model catalogs + mid-conversation routing + harness emulation** — OpenCode (models.dev), goose (registry/cost), OpenHands (RouterLLM/`switch_llm`), OIX (provider→harness auto-mapping). Boundary: `ctx.llm` + presets. *[clarified 2026-08-30: DSH ships a **model picker** — selecting a model sets the shared default, and per pinned docs a session that already sent a request retains its logged model (`docs/user/guide/providers.md`), so live mid-thread switching is the distinctive cohort bit (OpenHands `switch_llm`, Codex experimental turn/settings update). The surviving opportunity is routing *intelligence*: cost-aware catalogs, automatic router policies, harness emulation. Registry query for router/catalog plugins was rate-limited — ecosystem status unverified.]* Why: routing intelligence above the adapter registry is pure plugin layer.
13. **Cross-harness import/migration** — goose (CC/Codex/Pi session import), Codex (`externalAgentConfig`), OIX (portability-as-constraint). Boundary: sessions backend + embedding SDK.
14. **Sandboxed plugin subprocesses / tool-routing containers** — Cline (plugin sandboxing), Pi (Gondolin). Boundary: `ctx.subprocess` + `ctx.fs`.
15. **Stuck-detection & nudge** — OpenHands, OpenCode. Boundary: `agent/*` events.
16. **MCP Apps / mini-app UI surfaces** — Codex, goose (`goose_apps`, `io.modelcontextprotocol/ui`). Boundary: typed events + `ctx.webServer` slot.
17. **Durable work-orchestration state/protocol (Workboard)** — OpenClaw Workboard, resolved by [#33](https://github.com/S2P2/dsh-lab/issues/33) (`openclaw-workboard-delta.md` @ `533319b`): dependency-aware work cards, agent claim tokens + TTL/heartbeats, deterministic per-card worker-session routing, bounded dispatch (≤3 workers, one card per owner) with stale-claim recovery, `workboard_specify`/`workboard_decompose` tools, structured completion/block protocol with violation blocking, replay-safe notification cursors, and workspace-authority re-intersection at dispatch — 35 `workboard_*` tools, *itself implemented as an OpenClaw plugin, not a kernel primitive*. Boundary: DSH persistent teams + workflow scripts + session log — the durable coordination layer above subagent execution. Why: DSH has the primitives; nobody has composed the lease/dependency/dispatch protocol around them. Not a Core gap unless a plugin proves unable to hold durable cross-session claim state. *(Related split: OpenClaw parallel-specialist-lanes = Packaging gap — an ownership-contract/coordinator product pattern over existing primitives; `fleet` = per-tenant instance management, deployment not D8; `mantis` = QA evidence infra, Not applicable; `swabble` = macOS voice ingress, plugin-plausible under D10/D12.)*

### Packaging gaps (composition exists, nobody ships the package)

## 4. Cross-cutting patterns

- **Independent convergence on DSH's bets** — log-is-truth (OpenHands, Codex, Pi in-flight), Code Mode (Codex, OpenCode, OIX), bounded-context/KV-cache discipline (Codex's code-review rules mirror DSH's epochs), goals (nanobot nearly tool-for-tool, Codex `thread/goal`, CC), typed client protocols everywhere. The bets are winning; the differentiator is *composition* vs *productization*.
- **Safety doctrine spectrum** — DSH/NemoClaw/Codex confine (OS-level); goose/CC/OpenCode detect (LLM review stacks); OpenHands inverts the container. DSH's one-shot/freshness semantics remain the strictest in-process invariants in the cohort.
- **Editor↔runtime separation spectrum** — Cline (gRPC proto periphery + detached hub, strongest) > Codex app-server > OpenCode every-surface-is-client > DSH host/browser split > CC monolith-with-SDK. DSH is mid-spectrum; its ACP is automation-only.
- **Format-adoption graph** — Claude Code is the source node (SKILL.md, hooks vocabulary, marketplace layout → OpenHands, OIX, agentskills.io adopters with field-superset variance). DSH skills are compatible-adjacent; formal CC-format parity is cheap insurance.
- **Dependency edges into DSH** — `dsh-llm-pi-ai` wraps pi-ai (pinned 0.82.1 vs 0.84.3 HEAD at profiling); DSH's web-search-router already routes Codex models. The map is not cycle-free: DSH depends on two cohort members' surfaces.
- **Minimalism reveal** (nanobot) — channels+memory+cron+persona are "files + one bus" in the minimal harnesses; the expensive part in DSH terms is not the capability but the always-on host (core gap #3) — that asymmetry should shape any DSH roadmap ordering.
- **Docs-vs-source drift is endemic** — Eigent workflow canvas, Cline checkpoints, Codex README-vs-SDK serialization, UFO PiP: every profile that checked found drift; the map always cites the pinned tree, not the docs page.

## 8. Post-synthesis extensions (profiles #19–#20)

Admitted after first consolidation under the map's extension rule. Neither changes the normalized calls above beyond the counts noted; both add chart candidates.

**Open WebUI** (`open-webui.md` @ `d3e8bf3`) — the cohort's **multi-user self-hosted LLM workspace platform** (RBAC/groups/ACL/SCIM, per-user layered memory, 15-vector-DB RAG, OpenAI-compatible serving, OTel, horizontal scale) that has grown *inward* toward a harness: 256-iteration native-FC loop, ~60-tool catalog, RRULE automations that re-run the chat pipeline as the re-permissioned owner into shared channels, MCP HTTP bridge with OAuth DCR. Exec fully delegated out-of-core — no server-side sandbox in core. Grid deltas: D7 shipper +1 (per-user); D10 +1 (channels as human↔agent bus); a new core-gap flavor only Cloudflare OS shared — **multi-user/auth substrate** (DSH is loopback-by-design); D6 KV-prefix-cache discipline independently confirmed.
