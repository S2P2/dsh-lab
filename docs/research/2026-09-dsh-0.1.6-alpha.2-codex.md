# Using Codex with DeepSeek Harness 0.1.6-alpha.2

Date: 2026-09-20

## Summary

For a clean DeepSeek Harness `0.1.6-alpha.2` install, the most defensible Codex path is the first-party **Codex subagent** integration, not a community OAuth provider as the primary Harness model.

DSH 0.1.6-alpha.2 ships first-party support for `@deepseek-ai/dsh-subagent-codex`, but production profiles do not install/enable it automatically. The provider bundle must be installed into the chosen profile, the profile restarted, and a copied agent preset must expose the otherwise-disabled `subagent_codex` tool.

DSH's own provider guide for 0.1.6-alpha.2 says OAuth providers such as Codex are not yet supported by the normal built-in model-provider UI.

Community plugins can expose ChatGPT/Codex OAuth as a normal model provider, but current published compatibility evidence does not cover stock DSH 0.1.6-alpha.2:
- `dsh-codex-connect` explicitly lists 0.1.6-alpha.2 as undeclared/unverified.
- `dsh-codex-provider` says it was validated against DSH 0.1.0-rc.6.

## First-party path: Codex as a subagent

### 1. Install the provider bundle into the profile

For the default web profile:

```sh
dsh plugin --profile web add @deepseek-ai/dsh-subagent-codex
```

Restart the profile after installation:

```sh
dsh web
```

The 0.1.6-alpha.2 package documentation says the bundle supplies a compatible native Codex payload and registers a dormant `codex` subagent provider. Native Codex configuration/authentication remains authoritative.

### 2. Create a user copy of a full preset

The shipped `standard` preset contains the Codex delegation row but marks it `disabled: true`. DSH's preset-authoring guidance says to copy a shipped preset rather than editing the shipped copy.

User presets live under:

```text
${DSH_HOME:-$HOME/.dsh}/.agent-presets/<preset-id>/
```

A copied preset needs at least:
- `agent.cordis.yml`
- `preset.yml`

Use `standard` as the source for a normal full coding setup.

### 3. Enable the Codex tool row

In the copied `agent.cordis.yml`, find the existing row:

```yaml
- id: tool-subagent-codex
  name: '@deepseek-ai/dsh-tool-subagent'
  disabled: true
  config:
    provider: codex
    toolName: subagent_codex
    backgroundMode: one-shot
    maxDepth: provider-managed
```

Remove only:

```yaml
disabled: true
```

The resulting row should be:

```yaml
- id: tool-subagent-codex
  name: '@deepseek-ai/dsh-tool-subagent'
  config:
    provider: codex
    toolName: subagent_codex
    backgroundMode: one-shot
    maxDepth: provider-managed
```

Create a new session using that custom preset. The parent DSH agent can then delegate self-contained tasks to Codex via `subagent_codex`.

### 4. Authentication/model selection

The provider intentionally leaves authentication and model selection to native Codex configuration. It does not provide DSH-side OAuth login or model discovery. If the normal Codex product/CLI is already authenticated in the same environment, the subagent provider uses that native configuration.

The provider also supports a fixed `model` option on its host row if desired; if omitted, Codex's own native model settings are used.

## What this integration is and is not

Each delegation starts a fresh Codex app-server process, fresh ephemeral thread, and one turn. Codex receives the parent workspace cwd and the standalone delegated text task. It does not inherit the parent DSH conversation. The parent only receives Codex's final answer or a safe error result.

This is therefore useful for:
- delegating an implementation/review task to Codex;
- using Codex alongside a different primary DSH model;
- keeping parent and child contexts separate.

It is not equivalent to selecting a Codex model as the main DSH session model.

## Primary Codex model via ChatGPT OAuth

DSH 0.1.6-alpha.2's own provider guide says OAuth providers such as Codex are not yet supported in the built-in provider configuration.

Two community options exist, but neither currently has strong 0.1.6-alpha.2 compatibility evidence:

### dsh-codex-connect

Repository: https://github.com/franksong2702/dsh-codex-connect

Its current installation runbook explicitly says its published compatibility matrix covers selected 0.1.2 and 0.1.5 releases, and that stock DSH 0.1.6-alpha.2 remains undeclared/unverified. Do not infer compatibility from the older rows.

### dsh-codex-provider

Repository: https://github.com/Hu9956/dsh-codex-provider

It exposes ChatGPT/Codex OAuth and an `openai-codex` provider, but its documentation says the current version was validated against DSH 0.1.0-rc.6. Its peer dependency ranges are broad enough that installation may be attempted on later DSH versions, but that is not evidence that 0.1.6-alpha.2 is working.

## Recommendation for this clean 0.1.6-alpha.2 install

Use the first-party `@deepseek-ai/dsh-subagent-codex` integration now. Treat community primary-provider plugins as experimental until one publishes explicit 0.1.6-alpha.2 verification.
