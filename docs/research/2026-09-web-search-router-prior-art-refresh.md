- **Signals relevant to the spec's cross-cutting mechanics.** Recent commits show mature treatment of exactly the mechanics issue #8 needs: "fix(search): bound total request time and response bytes (#135)", "fix(auth): bound public authentication diagnostics (#127)" ([commit](https://github.com/franksong2702/dsh-codex-connect/commit/92335ea6252ed120366e8b53c3db4c358bc2890e), see §4c), "fix(settings): atomically save edited fields with revision checks (#131)", "fix(auth): honor cancellation before credential commit (#129)", "fix(proxy): bound shutdown and abort owned connections (#136)", "reconcile cancellation state and identify revoked refresh grants (#148)", "docs(security): describe explicit search routing behavior (#134)" (commit log).

**Risk assessment:** very high cadence and the strongest compatibility bookkeeping in the ecosystem, but 40 alpha releases in four weeks means any pinned dependency will churn; it is a *running plugin* to install, not (as far as this sweep could see) a library other plugins import. Whether its Codex search pieces are usable as a wrapped dependency — the August §4 pattern — is precisely the other agent's export-surface question. The safest framing for the implementation PR: keep the August §4 Yan-Zero wrapper as the default plan; treat codex-connect as the live-profile runtime whose behavior the Router must coexist with (it registers its own opt-in search routing), and let the surface deep-dive decide if it can also be the library.

## 4. Non-search (and cross-cutting) prior art for the revised spec (research question 4)

Four mechanics, each with the best current implementation found. All examples below are new since the August doc unless noted.

### 4a. Settings card with enable/disable/reorder (spec stories 3–4)

**chendefine/dsh-web-search-aggregation** (MIT, created 2026-08-23, [dsh.plugin.json](https://github.com/chendefine/dsh-web-search-aggregation/blob/main/dsh.plugin.json) v0.1.9; peer-depends on `@deepseek-ai`-family packages (`cordis >=4.0.1-rc.1`, `dsh-credentials`/`dsh-settings`/`dsh-web >=0.1.1-rc.1`) — [package.json](https://github.com/chendefine/dsh-web-search-aggregation/blob/main/package.json)). Its client card implements the exact ordered-list model the spec wants: queue entries carry a 1-based `position`, an `enabled` flag, and staged key lists where "tag order IS the order a save writes and the runtime reads" ([`src/client/controller.ts`](https://github.com/chendefine/dsh-web-search-aggregation/blob/main/src/client/controller.ts) lines 65–83); the card renders per-entry `moveUp`/`moveDown`/`removeEntry` buttons with aria-labels ([`src/client/card.tsx`](https://github.com/chendefine/dsh-web-search-aggregation/blob/main/src/client/card.tsx) lines 71–91) and a staged enabled checkbox ([`src/client/fields.tsx`](https://github.com/chendefine/dsh-web-search-aggregation/blob/main/src/client/fields.tsx) line 68), with API keys staged as masked closable tags (lines 135–162). Adapt the card/controller shape; avoid its multi-key rotation semantics (issue #8 is keyed credential refs, not key pools).

**weibaohui/dsh-continue** (session category; created 2026-08-31, no license file — adapt ideas, do not copy code) demonstrates an **ordered rule table edited in a visual settings editor**: rules are matched by first-match array order ("array order = priority; first matching, not-yet-exhausted rule wins", [`src/index.js`](https://github.com/weibaohui/dsh-continue/blob/main/src/index.js) lines 193–208) over a closed failure vocabulary `['rate-limit','quota','auth','context','server','transport','interrupted','status','any']` (lines 55–61, defaults at 76–79). Non-search proof that ordered-list settings + closed failure taxonomy compose.

### 4b. Deadline/budget + AbortSignal (5s attempt / 15s overall, abort wins)

**rogerdigital/dsh-searxng `src/search-session.ts`** ([file](https://github.com/rogerdigital/dsh-searxng/blob/main/src/search-session.ts); added by [`f6656ab6`](https://github.com/rogerdigital/dsh-searxng/commit/f6656ab6fe5ce8a9d5f1a8af1b1f2f4891174683), 2026-09-11) is now the strongest first-party-quality prior art for the spec's budget policy, matching it almost clause for clause:

- one total budget defaulting to **15 s** spanning pacing wait, backoff, and every network attempt (commit message; `totalBudgetMs` at line 39, deadline at 220);
- per-attempt timeouts **clamped to the remaining budget**: `Math.min(this.perAttemptTimeoutMs, Math.ceil(remaining))` (lines 226–234), with `remaining <= 0` failing fast (line 227);
- **Retry-After honored but never allowed to exceed the deadline** ("a delay that no longer fits" throws, lines 269–271; parser at 323); HTTP 429 gets at most one backoff attempt, attempts capped at three (commit message);
- **caller abort wins everywhere**: an already-aborted caller is rejected even on a cache hit (line 212), pacing queue waits reject with `SearxngClientError('caller-abort', …)` (line 100), and backpressure is honest — a full pacing queue rejects immediately instead of holding the caller (commit message).

Also strong: **chendefine**'s provider composes caller abort with per-attempt timeout via `AbortSignal.any([signal, timeout.signal])` and distinguishes timeout vs caller-abort outcomes ([`src/provider.ts`](https://github.com/chendefine/dsh-web-search-aggregation/blob/main/src/provider.ts) lines 169–198), checking `signal?.aborted` before every attempt (line 113) and surfacing `WebError('aggregated search aborted', 'WEB_ABORTED')` (line 253); **A3Boy/dsh-web-tools**'s pure fallback policy makes `aborted` the only TERMINAL kind — "the whole chain must stop immediately, never continue to the next provider" ([`lib/host/fallback.js`](https://github.com/A3Boy/dsh-web-tools/blob/main/lib/host/fallback.js) module doc; `TERMINAL = new Set(["aborted"])`). All three agree with the revised spec's abort-beats-fallback rule; adapt rogerdigital's budget math, chendefine's signal composition, and A3Boy's kind sets.

### 4c. Sanitized model-facing errors, operator detail in host logs

**franksong2702/dsh-codex-connect `src/auth-error.ts`** ([file](https://github.com/franksong2702/dsh-codex-connect/blob/main/src/auth-error.ts), from bounded-diagnostics commit [`92335ea6`](https://github.com/franksong2702/dsh-codex-connect/commit/92335ea6252ed120366e8b53c3db4c358bc2890e)) implements the spec's "closed taxonomy + sanitized model-facing error" exactly: "Public diagnostics never include arbitrary provider messages or nested causes" — a fixed `REQUEST_AUTH_MESSAGES` vocabulary, a `PUBLIC_MESSAGES` allowlist, and `publicAuthError()` that "return[s] a bounded diagnostic from a closed vocabulary, never upstream response text".

**240xu/dsh-websearch `lib/util/log.js`** ([file](https://github.com/240xu/dsh-websearch/blob/main/lib/util/log.js), landed in v2.2.0 [`b8826df2`](https://github.com/240xu/dsh-websearch/commit/b8826df224f40d61e35577410f4d4898f10d9af8b)) documents an ecosystem constraint the Router must respect: plugin diagnostics go to `ctx.logger` **because the session ledger's event vocabulary is a closed generated set** (`@deepseek-ai/dsh-session` known-event-types) and "a third-party plugin writing custom types … poisons the whole session log: writes succeed, the next continue/load refuses" (module doc, lines 1–17). Its emitters are best-effort/never-throw, never include secrets, and truncate bodies to 200/500 chars (lines 22–31 and `recordBackendOutcome`). Combined with v2.4.0's "error truncation" commit, this is the operative pattern for the Router's model-facing-vs-operator error split.

### 4d. Bounded in-memory diagnostics/health stores

No exact "last-20 content-free ring" was found in the ecosystem; the closest current shapes:

- **A3Boy/dsh-web-tools `lib/host/provider-health.js`** ([file](https://github.com/A3Boy/dsh-web-tools/blob/main/lib/host/provider-health.js), MIT, 26 stars): deliberately minimal in-memory `Map` keyed by provider with `retryAfterUntil` + `lastFailureCode`, lazy expiry on read ("no timer bookkeeping"), a `snapshot()` for the UI, and documented invariants — "cooldown is per PROVIDER, never per key", "auth/abort never write cooldown", "cooldown does NOT change fallbackOrder — it only degrades availability", state "in-memory only (process restart is fine to lose it)". This is issue #8's passive-health module almost verbatim; the same repo's `lib/host/fallback.js` keeps the retryable/terminal classification pure and testable.
- **codex-connect**'s "bound public authentication diagnostics" (#127, above) bounds what is *exposed* rather than retaining history; and **fno2010**'s 0.3.1 `/web-search-ext/health` route + Health tab (§2) shows the diagnostics surface pattern on a settings card.

Verdict: the 20-entry ring itself remains novel Router code (as August §8 concluded); reuse A3Boy's store shape and codex-connect's exposure rules around it.
